## 1. System overview

```
 Browser · skywyrm.io (GitHub Pages)              Cloud Run · wyrm-server (us-west1, max 1 instance)
 ┌───────────────────────────────────┐  HTTPS    ┌──────────────────────────────────────────┐
 │ index.html + ES modules, no build │─/api/rooms▶│ server.js  HTTP + WebSocket, limits      │
 │  main.js    loop, screens, lives  │◀───────────│ rooms.js   Registry · Room tick 30 Hz     │
 │  sim.js     shared simulation ◀───┼─same file──┼▶ ../site/js/shared.js (sim, bots, perks…)│
 │  render.js  three.js 0.163        │  WSS /ws   │ store.js   room list, daily totals        │
 │  net.js     online client         │◀══JSON════▶└───────────────┬──────────────────────────┘
 └───────────────────────────────────┘                            │
                                                  Firestore `rooms` and `stats` collections
```

**The simulation runs in three modes**, all from one file, `site/js/sim.js`:

| Mode | Where | What it simulates |
|---|---|---|
| `solo` | browser | Everything: the player, bots, collisions, food and power-ups |
| `client` | browser, online | Only your own dragon's flight. Everything else comes from the server (`sim.js:940-952`) |
| `server` | Cloud Run | Everything except human pose, which each client reports and the server speed-checks (§4.1) |

**Stack**
- Plain ES modules with no bundler and no framework.
- three.js 0.163.0, self-hosted at `site/vendor/` and mapped by an importmap in `index.html`.
- Fonts self-hosted as subsets in `site/fonts/`. A Content-Security-Policy meta tag allows only this site plus the game server (and localhost for testing).
- Node 22 with `ws` 8.22 and `@google-cloud/firestore` 9.3.
- No TypeScript.

## 3. Simulation (`site/js/sim.js`)

### 3.1 World and step
- **Units are metres and seconds.** Arenas are built by `makeArena` (`sim.js:24-43`):

| Arena | Shape | Size | Physics |
|---|---|---|---|
| `sky` (Skyhold) | cylinder | R 350, floor at y=0, no ceiling | gravity; centre at (0,70,0) |
| `orb` (The Orb) | sphere | R 325 | zero-G |

  Both arenas have `obstacles: []`. The capsule and sphere obstacle code at
  `sim.js:45-52` is unused.
- **Step timing:**
  - Solo: the frame dt is capped at 0.1 s, then split into sub-steps of at most
    1/60 s (`main.js:650,671`).
  - Server: a fixed 1/30 s step with an accumulator capped at 0.25 s
    (`server.js:164-170`).
- **`step(dt)` order** (`sim.js:937-964`):
  1. Clear events.
  2. For each live dragon:
     - a bot `think`
     - `updateHeat`
     - move: `fly` for local dragons; on the server, `applyNet` + `upkeep` for
       remote humans
     - `updateBreath` (dragonfire)
  3. Rebuild every dragon's beads. In `client` mode the step stops here.
  4. `buildHash` (4 m cells) → `collide` → `updateOrbs` → `updatePowerups`.
  5. Encounter stats, for the dev panel.

  The bot population (`managePopulation`, `bots.js`) is run by the caller
  (`main.js`, `rooms.js`), not by `step`.
- **Events** (`emit`) drive every toast, sound and voice line in the UI.
  On the wire, the server shortens some names: `fire`, `pu`, `nm`, `shield`,
  `miss` and `empty`.

| Event | Event | Event |
|---|---|---|
| `death` | `eat` | `bite` |
| `sever` | `fireStart` | `fireMiss` |
| `powerup` | `powerupSpawn` | `shieldPop` |
| `thrustEmpty` | `tier` | `nearMiss` |

### 3.2 Dragons
- **Body path:** a history of up to 1200 points, 0.5 m apart (600 m of path).
  - Beads sit every 0.7·r along it, with at most 900 per dragon.
  - The drawn length (`shownLen`) is the length of path actually flown.
  - The leaderboard ranks by mass.
- **Size:**
  - `lengthFor(m) = min(400, 8 + 0.4m)`
  - `radiusFor(m) = 0.6 + 1.4·min(1, m/2000)`
  - Length eases toward its target at +12 m/s when growing and −30 m/s when
    shrinking.
- **Movement** (`move`, `sim.js:453-512`):
  - One quaternion per dragon.
  - The steering stick sets a single rotation axis, so pitch and yaw happen
    together.
  - Response times: stick τ 0.06 s, speed τ 0.35 s; velocity trails the nose
    with τ 0.10 s.
  - Auto-level runs at 120°/s with gravity. The zero-G assist runs at 60°/s and
    fades while you pitch.
- **Speed:**
  - `speedX = 1 + 0.4·temp/100 + sizeSpeed(m)` (`sim.js:329-332`).
  - `sizeSpeed(m) = min(1, 0.5·((L−12)/88)^0.62)`, where L is the *target*
    length (`tunables.js:243-247`).
  - `speedX` multiplies cruise and boost, not brake.
  - The highest possible value is 2.4×.
- **Heat** (`sim.js:922-934`):
  - Target = 10 + 60·exp(−(dist/0.35R)²) + 35·min(1, nearby/5), capped at 100.
  - "nearby" counts other dragons within 35 m.
  - Warming uses τ 3 s and cooling τ 7 s.
- **Thrust** (`sim.js:561-582`):
  - Capacity is 10 s × (1 + 0.6·temp/100) × the perk multiplier.
  - Drains 1 s per second of boost and refills 0.4 s per second off-boost.
  - Running empty locks boost until min(1.5 s, capacity) has refilled.
  - Boosting burns 4 mass/s, with a floor of 14. Half of that drops as orbs worth 1.

### 3.3 Collisions (`collide`, `sim.js:662-751`)
- **Hazards:** `hazardDist < r` kills, with the surface as the cause. This is
  checked *before* spawn protection and the shield.
- **Head into a tail:** the hit radius is head r × 1.0 + tail r × 0.8. The
  nearest bead decides what happens:
  - **Bite:** if the bead index is ≥ max(4, nBeads − `biteBeads`) and `tailBite`
    is on. The victim loses up to 5 beads' worth of mass and the biter gains
    `biteBeads × biteMult` = 25. Bites have a 0.5 s cooldown.
  - **Death:** any other bead, unless the shield absorbs the hit (shield → 0,
    1.5 s protection).
- **Head-on:** the heavier dragon wins if it is more than 5% heavier; otherwise
  both die. This is skipped if either dragon is protected.
- **`kill`:** drops 80% of the dragon's mass as orbs worth about 6, with a 45 s
  TTL, and credits the killer. Bots respawn after 2–4 s.
- **Spawn** (`sim.js:343-406`):
  - The best of 16 candidates on a ring at 0.25–0.55 R, at least 15 m from any
    hazard and as far as possible from other heads and tails.
  - Spawn protection lasts 3 s and is extended while inside a tail.
- **Wall assist** (`sim.js:413-442`), always on for players:
  - Looks max(20 m, 1.8 s × speed) ahead.
  - Steers along the surface reflection with an inward bias.
  - Cancels boost above 0.45 urgency and forces brake above 0.7.
  - It runs on the client only. Walls still kill.

### 3.4 Food and power-ups
- **Food:**
  - A target of 2,000 ambient orbs worth 1 each, with a hard cap of 6,000 orbs
    (`sim.js:287-308`).
  - Each spawn draw makes a cluster of 20–40 orbs 60% of the time.
  - 85% of draws are Gaussian around the centre (σ 0.2R); the rest are uniform.
  - The pickup radius is 2 × `pickupMult` + r; Lodestone raises it to 18 + r.
  - Orbs are reeled into the mouth rather than vanishing (`sim.js:792-826`).
  - Bots above mass 400 get half value.
- **Power-ups** (`sim.js:833-863`):
  - The first appears at 10 s, then every 20 s ±25%, with at most 5.
  - The type pool is `shield, magnet, fire, fire`.
  - They are placed at food hotspots.
- **Dragonfire** (`sim.js:866-918`):
  - One charge gives a 1.2 s breath. The cone is 30° wide and 24 m (+r) long.
  - It hits the nearest enemy bead with index ≥ 3, so it never hits a head.
  - It cuts once per breath, trims the rest of the breath to 0.25 s, then calls
    `sever`.

### 3.5 Rules layer and tunables
- **`World.rule(k)`** returns `world.rules[k] ?? T[k]` (`sim.js:325`). Every newer
  mechanic reads through it, so a room can override it:

| Rule | Default | Rule | Default |
|---|---|---|---|
| `tailBite` | 1 | `aggrStart` | 0.25 |
| `biteBeads` | 5 | `aggrRampMin` | 15 |
| `biteMult` | 5 | `botAggrMax` | 1 (0.5 in every real game) |
| `lives` | 3 | `perks` | 1 |
| `respawnDelay` | 3 | `lengthSpeed` | 0.5 |
| `botMoods` | 1 | `lengthSpeedExp` | 0.62 |
| | | `lengthSpeedMax` | 1 |

- **Beginner rules:** solo (`main.js:453`) and every room (`rooms.js:27,100`) apply
  `BEGINNER_RULES = {botAggrMax: 0.5}`.
- **Not in the rules layer:** `powerups`, `dragonfire` and `botAggression` are
  read straight from `T`, so a room can't override them.
- **`T` is one shared object.**
  - Solo applies local overrides from `wyrm.tune.v2`.
  - Online, the server's `T` and rules replace it on `welcome` (`net.js:60-75`),
    and are restored when you leave.
  - The server can be retuned with the `WYRM_TUNE` JSON environment variable.
  - The full list is in Appendix A.

### 3.6 Bots (`site/js/bots.js`)
- **Thinking:** each bot thinks every 0.08–0.16 s, depending on its skill
  (0.6–1.0).
- **Avoidance** probes the nose, the midpoint, the goal and 16 feelers on two
  cones (30° and 65°). The look distance is (7 + 0.55·speed)·(0.8 + 0.3·skill).
- **Moods** (`bots.js:17-38`):
  - Grazer (hunt 0), sunbather (0.8), hunter (1.6), kingslayer (1).
  - Mood weights shift toward hunters and kingslayers as aggression A rises:
    [0.4−0.25A, 0.4, 0.12+0.4A, 0.03+0.17A].
- **Aggression:** A = min(`botAggrMax`, a0 + (1−a0)·min(1, age/(15 min))).
  - Age counts from when the room last woke (`world.ageStart`).
  - With the 0.5 cap, A tops out after about 5 min.
- **Population:** target = min(30, 3 + ⌊t/20 s⌋), minus humans online.
  - Extra bots retire farthest from the player first.
  - The menu's attract mode uses 30.
- **Gentle period:** in solo, during your first 3 runs, bots ignore you for 45 s
  after you spawn (`main.js:136`).
- **Names:** 44 dragon-style names, deduplicated.

## 4. Multiplayer

### 4.1 Who decides what
- **The server is the authority for:**
  - bots
  - collisions, deaths, bites and sever
  - food and growth
  - power-ups
  - heat and thrust
- **The client is trusted for:** its own pose.
  - It flies its dragon locally and sends a pose 30 times a second.
  - The server's `World.applyNet` (`sim.js:532-561`) keeps a movement budget:
    - top = (boost or cruise speed)·speedX + dive + 1
    - refills at top·dt·1.15
    - capped at half a second's worth
  - Anything beyond the budget is clamped, and `me.c` tells the client to
    hard-snap back (`net.js:154`).
  - Bank is clamped to ±1.2. A quaternion is accepted only if its length² > 0.5.
- **Other dragons** are drawn 120 ms in the past, interpolated from up to 8
  samples. Position may extrapolate to ×1.5 (`net.js:11,223-239`).
- **There is no client prediction or reconciliation** beyond that snap.

### 4.2 Rates

| Item | Value |
|---|---|
| Server tick | 30 Hz, from a 60 Hz `setInterval` with an accumulator capped at 0.25 s |
| Snapshots | 15 Hz (`SNAP_EVERY = 2`) |
| Client pose | 30 Hz |
| Ping | every 2 s |
| Lobby poll | every 5 s, menu only |
| Sweep | every 60 s |

### 4.3 Wire protocol
- The protocol is JSON text frames only. A binary frame closes the socket.
- Positions are rounded to 2 decimal places and quaternions to 3.

| Direction | Message | Contents |
|---|---|---|
| C→S | `hello` | `{name, perks[], skin}`. Must be the first message, within 5 s |
| C→S | `p` | `{x,y,z,qx,qy,qz,qw,s,bk,b,k,f}`: pose, speed, bank, boost, brake, fire |
| C→S | `spawn`, `park`, `unpark`, `ping{c}` | |
| S→C | `welcome` | `{you, room, tune, rules, time, dragons[meta], orbs[flat×7], pu}` |
| S→C | `s` (snapshot) | `tm`. `d`: `[id,x,y,z,qx,qy,qz,qw,mass,len,flags,bank,speed]` per dragon. `o`: food changes. `pu`. `lb`: top 10. `n`, `h`: counts. `me`: your own heat, thrust, fire, shield, magnet, kills and correction |
| S→C | `dn` / `dx` | A dragon appears (meta plus a tail path at 1 cm precision, every other point, ≤600 points) / leaves |
| S→C | `e` | Events: `death`, `sever`, `fire`, `bite`, `land`. Also personal events: `eat`, `tier`, `nm`, `pu`, `shield`, `miss`, `empty`, `park*` |
| S→C | `full` | The room is full |

- **Flag bits** in `d`:

| Bit | Meaning | Bit | Meaning |
|---|---|---|---|
| 1 | alive | 32 | breath |
| 2 | boost | 64 | human |
| 4 | brake | 128 | bot |
| 8 | protect | 256 | magnet |
| 16 | shield | | |

- **WebSocket close codes:**

| Code | Reason |
|---|---|
| 4000 | no hello within 5 s |
| 4002 | more than 5 bad messages |
| 4003 | room full |
| 4008 | rate limit or binary frame |

- **Compatibility rule.**
  - The site (GitHub Pages) and the server (Cloud Run) deploy separately, and
    phones cache the site.
  - So any protocol change must accept the previous message shape for at
    least one release.
  - There is no version field.

### 4.4 Rooms (`server/rooms.js`)
- **Defaults:** `the-orb` ("The Orb", orb) and `skyhold` ("Skyhold", sky).
  Both are permanent and beginner.
- **Names of created rooms** are generated, never typed: an adjective and a
  noun from the lists in `names.js` (24 × 24, e.g. "Jade Peak"), checked
  with `isRoomName`. The names test checks that every pair passes the room
  filter against the reserved names (`RESERVED_ROOM_NAMES`: The Orb,
  Skyhold, Skyhold Nest, Skyhold (Beginners), Skyhold Beginners, Nest and
  Orb, plus the reserved words in `names.js`) and that no word contains one.
- **Limits:**

| Item | Value |
|---|---|
| Humans per room | 30 |
| Bots per room | fill to 30 − humans |
| User rooms at once | 30 (503 when full) |
| Room creations per IP | 3 per hour (429), counted in memory |

- **Create** (`POST /api/rooms`):
  - Requires an allowed origin, JSON content and a body of at most 1 KB.
  - Then checks, in order: the per-IP rate limit and the global cap.
  - The name is the `name` asked for if it's a list name not in use;
    anything else (a taken name, or free text from an old cached client)
    gets a random unused list name. The name never fails a create.
  - The `beginner` field is ignored, so every room is a beginner room.
  - The room id is 9 random bytes in base64url: 12 characters, about 72 bits.
- **Lifecycle:**
  - A room's world is created on its first join, with a 10 s warm-up run before
    players arrive (`rooms.js:106`). It is freed after 10 min empty.
  - Expiry: `expireAt` is set to now + 12 h when a room is created or becomes
    empty, and cleared while anyone is in it. Expired rooms are hidden and then
    swept.
  - On start, saved rooms whose names aren't list names (typed before names
    were generated) are dropped and deleted from the store.
- **Join:** caps the room's humans, then runs `safePlayerName`, `cleanPerks`
  and `skinById`. It spawns at mass 10, sends `welcome` and broadcasts `dn`.
- **Leave:** drops 80% of the dragon as loot and broadcasts `dx`.
- **Respawn:** refused while alive, while parked, or within 1 s of a death. The
  server doesn't enforce lives; the client counts them.
- **Park** (online pause, `rooms.js:188-226`):
  - A 3 s countdown during which you are still hittable, then you are removed
    with your mass and kills kept.
  - You can unpark after 2 s, and you return at a safe spawn point with
    protection.
- **Per-room `meta.rules`:** merged in at `rooms.js:100` but never set. The
  hook exists for future modes.

### 4.5 Persistence (`server/store.js`)
- **Which store:**
  - Firestore when `STORE=firestore`, or on Cloud Run unless `STORE=memory`.
  - Otherwise an in-memory Map.
- **What is stored:**
  - The room list, in the `rooms` collection:
    `{id, name, arena, beginner, permanent, createdAt, expireAt}`.
  - The anonymous daily play totals (§4.7), in the `stats` collection: one
    document per UTC day, id `YYYY-MM-DD`. The server keeps 30 days and
    deletes older ones, so the collection stays at about 30 small documents.
- **Game state** is held in memory only. A restart drops every dragon.
- **Writes are fire-and-forget.** Errors are logged and ignored.
- **Totals:** the current day is written at most once a minute, only when it
  changed, and again on SIGTERM. Recent days are loaded on boot, so a restart
  or deploy doesn't zero the day.
- An optional Firestore TTL policy on `expireAt` can act as a backstop.

### 4.6 Endpoints and limits (`server/server.js`)

| Endpoint | Notes |
|---|---|
| `GET /healthz` | `ok` |
| `GET /api/rooms` | The room list. CORS headers are sent only for allowed origins |
| `POST /api/rooms` | §4.4 |
| `POST /api/run` | One solo life's anonymous numbers (§4.7). 204, or 400 / 403 / 413 / 415 / 429 |
| `GET /api/stats` | The public daily totals, newest day first. `Cache-Control: public, max-age=60` |
| `OPTIONS` | 204 for an allowed origin, else 403 |
| `WS /ws?room=<id>` | Checks path, origin, room and the per-IP cap |

- **Origin allowlist:**
  - `ALLOWED_ORIGINS` defaults to `https://skywyrm.io,https://www.skywyrm.io`.
  - Off Cloud Run, or with `ALLOW_LOCALHOST=1`, any localhost or 127.0.0.1 port
    is also allowed.
  - A missing Origin header is accepted only in dev.
- **Client IP:** the last `X-Forwarded-For` entry. It is held only in
  memory, for the per-IP limits below, and never stored or logged.
- **Limits:**
  - 6 sockets per IP.
  - 20 run notes per IP per hour (`POST /api/run`), counted in memory and
    swept every minute. The body is at most 512 bytes.
  - 2 KB maximum frame.
  - A token bucket of 90 messages burst, refilling at 60 per second.
  - Outbound frames are dropped while more than 512 KB is buffered.
- **Response headers:** `no-store` (except `/api/stats`), `nosniff`, `Vary: Origin`.
- **Server-side checks on what clients send:**
  - Names go through `names.js`.
  - Perks and skins must be known ids, with at most 2 perks. The rank that
    unlocks them is *not* checked.
- **`?server=` override:** honoured only on a localhost page, and only for
  localhost or `*.run.app` targets (`net-config.js:8-15`).

### 4.7 Play totals (`server/stats.js`)
The improvement loop's numbers, kept without identifying anyone
([privacy.html](../site/privacy.html), PRD §11).
- **What a life reports:** world (`sky`/`orb`), peak length (m), seconds
  flown, kills, and how it ended: `wall` (any arena edge, including the cloud
  sea), `body` (a tail), `headon`, `quit`, `disconnect` or `other`. Dragonfire
  and heat don't kill, so they have no cause yet; a new cause counts as
  `other` until it is added.
- **Solo:** at the end of each solo life (`main.js` `reportLife`, next to
  `bankLife`, and when you leave to the menu), the browser sends one note:
  `fetch(serverUrl() + '/api/run', {method: 'POST', keepalive: true})` with a
  `text/plain` body `{v: 1, mode: 'solo', arena, len, secs, kills, cause}`.
  Text/plain keeps it a simple CORS request (no preflight). There is no id,
  cookie or name, and every failure is ignored. It is skipped when
  `SERVER_URL` is `''` and never sent for online lives.
- **Checks:** allowed origin, `text/plain` or JSON, at most 512 bytes, the
  per-IP limit, then `cleanRun`: `v` must be 1, `mode` `'solo'`, `arena` a
  known world, and the numbers finite. Numbers are clamped and rounded (length
  0–2000, seconds 0–7200, kills 0–500). An unknown cause becomes `other`.
  Other fields are dropped.
- **Rooms:** the server counts its own humans' lives (`Room.startLife` and
  `endLife`). A life ends on a death, on leaving with the dragon still flying
  or parked (close code 1000, 1001 or 1005 is `quit`; anything else is
  `disconnect`), or on SIGTERM (`disconnect`). Time parked is left out, and
  the peak length survives a park.
- **Per day and source** (`solo`, `room`): `runs`, `secs`, `kills`, `maxLen`,
  a peak-length histogram (`0-15`, `15-25`, `25-50`, `50-100`, `100-200`,
  `200+` m; a new dragon is 12 m), counts by `cause` and by `arena`. Plus, per
  day: `peakHumans` (all rooms at once, checked on each join and every minute)
  and `roomsCreated`.
- **Compatibility:** an older server answers `/api/run` with 404, which the
  page ignores. Older pages send nothing, and their room lives are still
  counted. The WebSocket protocol is unchanged.

## 5. Client

### 5.1 Boot and loop (`main.js`)
1. **`carryOver()`** imports a `#carry=` fragment (base64url JSON `{p, s}`) into
   `wyrm.profile.v1` and `wyrm.settings.v1`, but only when those are empty. It
   then strips the fragment. This was built for the move from dendroslabs.com;
   that page is gone now, so this code can be removed.
2. **Load the profile and settings.** `settings.beginner` is forced to true.
3. **Build the attract world:** 30 bots, warmed up with 25 s of simulation.
4. **Each frame:**
   - Inside a try/catch (the crash guard):
     - input
     - sim (solo) or net (online)
     - camera
     - HUD at 4 Hz for the leaderboard
     - render
     - audio
   - If a frame throws, it is recorded, and the next `requestAnimationFrame` still
     runs.
5. **Lives:** counted in `main.js:76-104,223-273`. `bankLife` turns each life into
   jade, and `reportLife` sends a solo life's anonymous numbers (§4.7).

### 5.2 Robustness
- **Crash guard** (`main.js:607-646`):
  - `noteProblem(kind, err)` stores the last problem in `wyrm.crash.v1`:
    `{kind, msg, at, state, online, ua}`.

- **WebGL context loss:** the game calls `preventDefault`. On restore it forces
  Low quality.
- **Cache stamps:**

  - When a file changes, its stamp must be bumped in *every* file that references it.

## 6. Rendering (`site/js/render.js`)

### 6.1 Frame pipeline
1. **Main scene** → `mainRT`: HalfFloat, 4× MSAA on High, linear HDR.
2. **Cube camera:** 6 faces, rendered when wide view or the mirror is on. 768²
   every frame on High; 384² every other frame on Low.
3. **Bloom:**
   - Bright-pass at ¼ resolution: threshold 0.85, soft knee.
   - Then two separable 5-tap Gaussian rounds.
   - High only.
4. **Warp pass** to the screen:
   - **Sharp centre:** taken from `mainRT`.
   - **Edges:** the cube is warped with θ(r) = atan(tanHalf·r) + extra·(r/rMax)³, so
     the corners reach `wideCorner` = 122°.
   - **Rear mirror:** an inset rectangle at the top centre.
   - **Bloom:** added before tone mapping, centre only.
   - **Output:** ACES Filmic tone mapping (exposure 1.1), then sRGB encoding.

**Other renderer settings:**
- **Camera:** FOV 72°, near 0.1, far 3000.
- **Pixel ratio:** up to 2 on High, 1 on Low.
- **Auto quality:** starts on High and drops to Low once if the frame rate stays
  below 40 fps for a 5 s window. The drop isn't saved.

### 6.2 Environment
- **Skyhold:**
  - **Sky:** a camera-following dome at radius 1500, with a low-sun sprite.
  - **Fog:** FogExp2 0xC99A6E at 0.0015.
  - **Cloud sea:** an fbm shader disc that fades into haze.
  - **Karst pillars:** 26, each with pines (separate meshes, about 156 in total).
  - **Ink-wash ridges:** 3 rings.
  - **Range rings:** at y = 0.3.
  - **Storm wall:** 72 lines plus an additive "qi curtain" cylinder. It
    brightens as you approach (`warn` = clamp((14 − hazardDist)/10)).
- **The Orb:**
  - A nebula dome.
  - A latitude/longitude shell every 20°.
  - 1,500 stars.
  - FogExp2 at 0.0012.
- **Both worlds:**
  - A PMREM environment built from a tiny sky scene, for reflections.
  - A breathing heat sun at the centre: core, halo and corona.
  - Instanced blob shadows.

### 6.3 Dragon bodies: GPU tubes
- **Each body is one continuous tube.** All other dragons share one
  `InstancedBufferGeometry` built from `tubeRing(16, 2)`: 16 sides × 2 rings,
  64 triangles per segment.
- **Interleaved frame buffer:** `InstancedInterleavedBuffer`, stride 18 floats,
  DynamicDraw.
  - Every attribute is read twice, at offset `o` and at `18 + o`.
  - So instance *i* sweeps from spine frame *i* to frame *i+1*, with no seams
    or gaps in turns.

| Floats | Attribute | Meaning |
|---|---|---|
| 0–2 | `aP` | position, including the swim offset |
| 3–5 | `aR` | side axis |
| 6–8 | `aU` | back axis |
| 9 | `aM.x` | radius; **−1 marks a break** between dragons |
| 10 | `aM.y` | distance from the head in units of r |
| 11 | `aM.z` | tier + 8·bloodline |
| 12–14 | `aC` | colour 1, after the tail-tip gold, proximity glow and spawn ghosting |
| 15–17 | `aD` | colour 2 |

- **Spine frames:** rotation-minimising transport of `d.up`.
- **Cross-section:** 1.06 wide × 0.95 tall.
- **Radius profile:**
  - The neck starts at 0.7 and grows over the first 6 beads.
  - The last 15% tapers down to 0.4.
  - The last bead is ×0.05.
- **Swim wave** (drawing only; the simulation keeps the true path):
  - Amplitude r·1.05 (×0.6 for your own dragon), wavelength r·14.3, lift 0.35.
  - Phase follows the distance flown.
  - The frame tilts with the wave's slope.
- **Your own dragon:**
  - Drawn in its own tube (1,000 frames), translucent at 0.5 opacity with
    `depthWrite` off.
  - A depth-only pre-pass on the same geometry runs first, so only the
    front surface blends.
  - It shrinks within 3.5 m of the camera.
  - Fins, legs, plumes and the head stay opaque.

### 6.4 Scale shader (`dragonScales`, `render.js:1444-1540`)
- **Scales overlap like roof tiles.**
  - Rows are offset like bricks. The first hit among 3 candidate rows wins,
    so the scale nearer the head lies on top.
  - Each scale has a keel, a crevice shadow under its neighbour, a lip highlight
    and per-scale variation.
- **The bloodline picks the style**, from an FNV-1a hash of the dragon id
  (`render.js:1633`):

| Bloodline | Share of dragons | Scale grid (around × along) |
|---|---|---|
| Scaled | 50% | 13 × 1.9 |
| Feathered | 25% | 15 × 1.15, with quill and barbs |
| Armoured | 25% | 9 × 1.3, broad ridged plates |

- **Colour:**
  - Cream belly scutes with creases.
  - A darker back with slow mottling.
  - A dorsal stripe and some scales in colour 2.
  - An iridescent rim (emissive (1−|n·v|)³·0.3).
- **Relief:**
  - Screen-space derivative bump, with the slope clamped so it doesn't sparkle.
  - Roughness varies from 0.16 to 0.62.
- **Anti-aliasing:** scale edges use `fwidth`. Detail fades out when scales get
  smaller than a pixel (`scaleDetail`), and feather barbs fade to avoid moiré.
- **Tier effects:**
  - Elder+: scale lips are gilded.
  - Ancient: qi veins flow along the body, driven by the `BODY_TIME` uniform.

### 6.5 Heads (`dragonHeadParts`, `render.js:1731-1837`)
- **Parts:** built once from small helpers (`bone`, `lick`, `ruff`), merged per
  material, and shared by every head.
  - skull, snout, lion nose, brows, cheek frills, a 7-lick ruff
  - eyes with slit pupils, fangs
  - horn buds, deer antlers, a gold crown
  - CatmullRom whiskers, an 11-lick mane, a beard
  - a flaming pearl
- **Head skin:** uses the same scale shader. Antlers and the crown use a gold
  metal on Elder+.
- **Size:** r·(1.45 + 0.05·tier), ×0.85 for your own dragon.

| Tier | Head adds | Body adds |
|---|---|---|
| 0 | buds | fins |
| 1 | antlers | front legs (feathered dragons: plumes every 3rd bead) |
| 2 | mane and beard | back legs, plumes every 6th bead |
| 3 | crown, gold antlers, glowing eyes | gilding, 35% gilded plumes |
| 4 | pearl ahead | qi veins |

- **Jaw:** hinged at (0, −0.12, 0.2), with an opening angle of 0.6·open rad
  (about 34°). It opens fully when breathing fire or when `foodAhead()` finds
  food in reach.
  - `foodAhead()` is a scan run only for heads within 120 m.
  - Each bite snaps the jaw shut briefly.
  - A wedge-shaped cone fills the open mouth; its height is
    0.02 + 1.2·tan(gap/2).
  - The snout lifts by 0.22·open.
- **Look into turns:**
  - The turn rate comes from the quaternion change since last frame.
  - Yaw is clamped to ±0.8 and pitch to ±0.6, both ×`headLook` 0.3, smoothed
    with τ 0.12 s.
  - The head pivots 0.7 head-sizes back, so it stays on the neck.

### 6.6 Effects
- **Food:** one InstancedMesh of icosahedra, capped at 6,000. Colours are pushed
  above 1 so they bloom.
- **Power-up crystals** snap between shapes on a beat, like Tron's "Bit".
- **Dragonfire:** a pooled additive cone, plus 26 flame particles per frame.
- **Particles:** a single additive Points cloud, 4,000 drawn and 6,000 simulated.
- **Lodestone:** a rig of tori and glow sprites, plus up to 240 camera-facing
  tractor beams.
- **Leader beacon:** world-size glow sprites, plus constant-size star sprites
  with depth testing off, plus a point light and flames.
- **Proximity glow:** enemy beads within 7 m of your head whiten and pulse.
  This is computed per bead on the CPU.

## 9. Security and abuse

**In place:**
- No accounts, chat, ads, cookies or third-party analytics. Nothing secret in
  the repo, since Cloud Run uses its service account.
- **Play totals (§4.7)** are anonymous by construction: a note carries no id,
  name or cookie, the server adds it straight into daily counts, and
  `/api/stats` publishes only those counts. IPs are used only in the
  in-memory rate limits and are never stored or logged by the app. The
  privacy page (`site/privacy.html`) says exactly this.
- Production Firestore rules deny all browsers.
- Names are filtered on both the client and the server, and shown only with
  `textContent` or `fillText`. The filter (`names.js`):
  - folds accents to ASCII (José → Jose) and refuses any other letter, so a
    Cyrillic look-alike can't sneak a word past it
  - reads leetspeak, ph/ck/v sound-alikes, repeated letters and spaced-out
    letters
  - checks short words inside each word of a name, excusing innocent words
    they hide in (Grape, Peacock); `kys` and a few abbreviations only match
    as whole words
  - matches reserved words as whole words (Admin is taken, Systemic isn't)
- Room names are generated from word lists, never typed, so nothing a
  player writes is shown in every lobby (§4.4).
- The origin allowlist, rate limits and frame limits in §4.6.

**Risks**

| # | Risk | Notes |
|---|---|---|
| 1 | Room-creation denial of service | 3 creations per hour per IP and a 12 h lifetime for unjoined rooms. One address can fill all 30 slots in about 10 h. The per-IP counts reset on restart |
| 2 | Shared networks | 6 sockets per IP blocks the 7th player on one school or home network |
| 3 | Scripted clients | `Origin` can be forged and there is no auth. Pose is client-reported within the speed budget. Perks aren't checked against rank. Lives are client-only. Accepted for a kids' game |
| 4 | Dropped control frames | The backpressure dropper can drop `dn`, `dx` or `e`, not just snapshots. A missed `dn` hides that dragon until it rejoins |
| 5 | Client IP | Uses the last `X-Forwarded-For` entry. That's correct behind Cloud Run directly, but a load balancer in front would put every player behind one IP |
| 6 | Capacity | One thread runs every room, with no tick-overrun metric. A room waking runs a synchronous 300-tick warm-up that stalls the other rooms |
| 7 | Hourly disconnect | The 3600 s timeout ends every socket, with no reconnect |
| 8 | Third-party code | Fixed: three.js and the fonts are self-hosted and a CSP (meta tag) allows only this site and the game server. GitHub Pages can't send headers, so `frame-ancestors` isn't set |
| 9 | Unpinned builds | Lockfiles are committed and the image installs with `npm ci`; GitHub Actions are pinned by SHA. The Docker base image (`node:22-slim`) is still a tag, so it picks up Node security patches |
| 10 | Fake run notes | Anyone can post plausible solo notes (20 an hour per IP, more from many IPs) and skew the solo totals. Room totals are counted by the server and can't be faked this way. Read solo numbers as a trend, not exact counts |
| 11 | Host logs | Google Cloud's standard request logs (30 days) and GitHub Pages' logs record IP addresses, outside the app's control. The privacy page says so |
