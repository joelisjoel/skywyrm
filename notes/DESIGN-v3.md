## 1. System overview

```
 Browser · skywyrm.io (GitHub Pages)              Cloud Run · wyrm-server (us-west1, max 1 instance)
 ┌───────────────────────────────────┐  HTTPS    ┌──────────────────────────────────────────┐
 │ index.html + ES modules, no build │─/api/rooms▶│ server.js  HTTP + WebSocket, limits      │
 │  main.js    loop, screens, lives  │◀───────────│ rooms.js   Registry · Room tick 30 Hz     │
 │  sim.js     shared simulation ◀───┼─same file──┼▶ ../site/js/shared.js (sim, bots, perks…)│
 │  render.js  three.js 0.163        │  WSS /ws   │ store.js   room list, daily totals        │
 │  net.js     online client         │◀══JSON════▶└───────────────┬──────────────────────────┘
 └───────────────────────────────────┘                            │
                                                  Firestore `rooms` and `stats` collections
```

**The simulation runs in three modes**, all from one file, `site/js/sim.js`:

| Mode | Where | What it simulates |
|---|---|---|
| `solo` | browser | Everything: the player, bots, collisions, food and power-ups |
| `client` | browser, online | Only your own dragon's flight. Everything else comes from the server (`sim.js:940-952`) |
| `server` | Cloud Run | Everything except human pose, which each client reports and the server speed-checks (§4.1) |

**Stack**
- Plain ES modules with no bundler and no framework.
- three.js 0.163.0, self-hosted at `site/vendor/` and mapped by an importmap in `index.html`.
- Fonts self-hosted as subsets in `site/fonts/`. A Content-Security-Policy meta tag allows only this site plus the game server (and localhost for testing).
- Node 22 with `ws` 8.22 and `@google-cloud/firestore` 9.3.
- No TypeScript.

## 3. Simulation (`site/js/sim.js`)

### 3.1 World and step
- **Units are metres and seconds.** Arenas are built by `makeArena` (`sim.js:24-43`):

| Arena | Shape | Size | Physics |
|---|---|---|---|
| `sky` (Skyhold) | cylinder | R 350, floor at y=0, no ceiling | gravity; centre at (0,70,0) |
| `orb` (The Orb) | sphere | R 325 | zero-G |

  Both arenas have `obstacles: []`. The capsule and sphere obstacle code at
  `sim.js:45-52` is unused.
- **Step timing:**
  - Solo: the frame dt is capped at 0.1 s, then split into sub-steps of at most
    1/60 s (`main.js:650,671`).
  - Server: a fixed 1/30 s step with an accumulator capped at 0.25 s
    (`server.js:164-170`).
- **`step(dt)` order** (`sim.js:937-964`):
  1. Clear events.
  2. For each live dragon:
     - a bot `think`
     - `updateHeat`
     - move: `fly` for local dragons; on the server, `applyNet` + `upkeep` for
       remote humans
     - `updateBreath` (dragonfire)
  3. Rebuild every dragon's beads. In `client` mode the step stops here.
  4. `buildHash` (4 m cells) → `collide` → `updateOrbs` → `updatePowerups` →
     `updatePearls`.
  5. Encounter stats, for the dev panel.

  The bot population (`managePopulation`, `bots.js`) is run by the caller
  (`main.js`, `rooms.js`), not by `step`.
- **Events** (`emit`) drive every toast, sound and voice line in the UI.
  On the wire, the server shortens some names: `fire`, `pu`, `nm`, `shield`,
  `miss` and `empty`.

| Event | Event | Event |
|---|---|---|
| `death` | `eat` | `bite` |
| `sever` | `fireStart` | `fireMiss` |
| `powerup` | `powerupSpawn` | `shieldPop` |
| `thrustEmpty` | `tier` | `nearMiss` |
| `chill` | `bolt` | `acid` |
| `pearl` | | |

  `fireStart` carries `lv` (charges spent) and `el` (element); `fireMiss` carries `el`.

### 3.2 Dragons
- **Body path:** a history of up to 1200 points, 0.5 m apart (600 m of path).
  - Beads sit every 0.7·r along it, with at most 900 per dragon.
  - The drawn length (`shownLen`) is the length of path actually flown.
  - The leaderboard ranks by mass.
- **Size:**
  - `lengthFor(m) = min(400, 8 + 0.4m)`
  - `radiusFor(m) = (0.6 + 1.4·min(1, m/2000)) × (1 + girth·((L − 12)/88)^girthExp)`,
    with L = `lengthFor(m)`. Rule `girth` (1; 0 = the old thin dragons) and
    `girthExp` (0.585) make big dragons fatter than the thin radius at the
    same length: ×1 for a newborn, ×1.4 at 32 m, ×2 at 100 m, ×2.5 at 188 m,
    ×3 at 300 m, ×3.4 at 400 m. So r is 0.61 m at spawn, 1.52 m at 100 m,
    3.33 m at 300 m and 4.35 m at 400 m (mass 980), up to 6.76 m by mass
    2000; a body is about 45 times as long as it is thick from 200 m up
    (thin dragons went from 66:1 at 100 m to 156:1 at 400 m). The curve has
    the same shape as `sizeSpeed` and was picked from same-seed renders.
    `World.radius(m)` applies the room's rule (spawn, `upkeep`, and in the
    browser `net.js` `applyState`).
  - Everything sized by r follows: hitboxes, bead spacing (0.7r, so a fat
    dragon has fewer beads, wider apart, and a longer edible tip), the
    pickup reach (2 + r), power-up and pearl reach, the wall assist's
    margin, and in the renderer the head, jaws, fins, legs, plumes, tip
    feathers, swim wave, shadow and glows.
  - Length eases toward its target at +12 m/s when growing and −30 m/s when
    shrinking.
- **Movement** (`move`, `sim.js:453-512`):
  - One quaternion per dragon.
  - The steering stick sets a single rotation axis, so pitch and yaw happen
    together.
  - Response times: stick τ 0.06 s, speed τ 0.35 s; velocity trails the nose
    with τ 0.10 s.
  - Auto-level runs at 120°/s with gravity. The zero-G assist runs at 60°/s and
    fades while you pitch.
- **Speed:**
  - `speedX = min(speedCap, 1 + 0.4·temp/100 + sizeSpeed(m))`, with
    `speedCap` 4 (`sim.js` `speedMult`).
  - `sizeSpeed(m) = min(3, 0.5·((L−12)/88)^0.62 + 1.35·((L−200)/200)^1.5)`,
    where L is the *target* length and the second term only counts above
    200 m (`tunables.js` `sizeSpeed`).
  - `speedX` multiplies cruise and boost, not brake.
  - Before heat: ×1.5 at 100 m, ×1.8 at 200 m, ×2.5 at 300 m, ×3.6 at 400 m.
    A full-length dragon at full heat reaches the ×4 cap: 64 m/s cruising,
    104 m/s boosting.
- **Heat** (`sim.js:922-934`):
  - Target = 10 + 60·exp(−(dist/0.35R)²) + 35·min(1, nearby/5), capped at 100.
  - "nearby" counts other dragons within 35 m.
  - Warming uses τ 3 s and cooling τ 7 s.
- **Thrust** (`sim.js:561-582`):
  - Capacity is 10 s × (1 + 0.6·temp/100) × the perk multiplier.
  - Drains 1 s per second of boost and refills 0.4 s per second off-boost.
  - Running empty locks boost until min(1.5 s, capacity) has refilled.
  - Boosting burns 4 mass/s, with a floor of 14. Half of that drops as orbs worth 1.

### 3.3 Collisions (`collide`, `sim.js:662-751`)
- **Hazards:** `hazardDist < r` kills, with the surface as the cause. This is
  checked *before* spawn protection and the shield.
- **Head into a tail:** the hit radius is head r × 1.0 + tail r × 0.8. The
  nearest bead decides what happens:
  - **Bite:** if the bead index is ≥ max(4, nBeads − `biteBeads`) and `tailBite`
    is on. The victim loses up to 5 beads' worth of mass and the biter gains
    `biteBeads × biteMult` = 25. Bites have a 0.5 s cooldown. With rule
    `girth` the beads are counted at a thin dragon's spacing, so a bite
    costs what it did (9.7 mass from a 300 m dragon) though a fat tip is
    longer; the reach to bite it grows with r like every hitbox.
  - **Death:** any other bead, unless the shield absorbs the hit (shield → 0,
    1.5 s protection).
  - Skipped while the head is stunned by lightning (`d.stun`): it can't
    steer, so a body it's carried into doesn't count.
- **Head-on:** the heavier dragon wins if it is more than 5% heavier; otherwise
  both die. This is skipped if either dragon is protected or stunned.
- **Bead hash** (`buildHash`, `queryBeads`): beads go in cells, and a query
  looks one cell round a point, so a cell must be as wide as the farthest
  reach asked about: head + tail radius, or a bot feeler's pad. Thin
  dragons fit in 4 m. With rule `girth` on, the cell is
  max(4, 1.8·r + 1.5 m) for the fattest dragon alive (7.5 m with a 300 m
  dragon, 13.7 m at mass 2000); with it off, always 4 m. A busy room with
  two mass-2000 dragons kept alive costs about 2.1 ms a tick against
  1.3–1.6 ms thin.
- **`kill`:** drops 80% of the dragon's mass as orbs worth about 6, with a 45 s
  TTL, and credits the killer. Bots respawn after 2–4 s.
- **Spawn** (`sim.js:343-406`):
  - The best of 16 candidates on a ring at 0.25–0.55 R, at least 15 m from any
    hazard and as far as possible from other heads and tails.
  - Spawn protection lasts 3 s and is extended while inside a tail.
- **Wall assist** (`sim.js:413-442`), always on for players:
  - Looks max(20 m, 1.8 s × speed) ahead.
  - Steers along the surface reflection with an inward bias.
  - Cancels boost above 0.45 urgency and forces brake above 0.7.
  - It runs on the client only. Walls still kill.
  - It also runs for any stunned dragon, bots included (the only steering a
    stun allows).

### 3.4 Food and power-ups
- **Food:**
  - A target of 2,000 ambient orbs worth 1 each, with a hard cap of 6,000 orbs
    (`sim.js:287-308`).
  - Each spawn draw makes a cluster of 20–40 orbs 60% of the time.
  - 85% of draws are Gaussian around the centre (σ 0.2R); the rest are uniform.
  - The pickup radius is 2 × `pickupMult` + r; Lodestone raises it to 18 + r.
  - Orbs are reeled into the mouth rather than vanishing (`sim.js:792-826`).
  - Bots above mass 400 get half value.
- **Power-ups** (`sim.js:833-863`):
  - The first appears at 10 s, then every 20 s ±25%, with at most 5 random
    ones (sun crystals don't count toward the 5).
  - The type pool is `shield, magnet` plus two breath crystals
    (`breathCrystal`): `fire`, or with rule `elements` and probability
    `elementShare` 0.5 one of `ice`, `bolt` (lightning) or `acid`.
  - They are placed at food hotspots, at least 30 m from a wall, 20 m from
    the sun and within 0.55R of the centre.
  - **Drift** (`World.drift`, rule `powerupDrift` 1 m/s): each crystal flies
    at 0.6–1.4× that, easing (τ 2 s) toward a new random heading every
    3–8 s (half as steep in Skyhold). It heads for the centre within 30 m of
    a wall or the cloud sea or beyond 0.55R, and away from it inside 20 m.
    The server simulates it; positions already go out in every snapshot's
    `pu`, so old clients simply see crystals move. The renderer adds a
    bob and sway of up to 0.6 m (drawing only).
- **Sun crystals** (`updateSunCrystals`, `sunBirth`, `sunDrift`; rule
  `sunCrystals`):
  - One breath crystal of each flavour (`ELEMENTS`, or just `fire` with
    `elements` off; none with `dragonfire` off) is in `world.powerups` on
    top of the random ones, marked `pu.sun` = an id. `world.sunDue` maps a
    flavour to when its next one is born. A new world's first four are born
    1 s apart.
  - Born at `arena.center` with a `sunCrystal` event (kind, id, pos),
    heading out in a random direction (level ±20% in Skyhold). It can't be
    caught while `pu.hatch` (`sunCrystalHatch` 1.5 s) runs.
  - `sunDrift`: the aim is the straight line out from the sun (level in
    Skyhold) plus a sideways lean of 0.45, re-picked every 3–7 s and
    projected off the outward line, so the distance from the sun only grows.
    It flies at `sunCrystalSpeed` 4 m/s × 0.85–1.15, spat out at 3× that
    and easing down over about a second (velocity τ 1.5 s). Skyhold keeps it
    between 50 m above the cloud sea and 50 m above the sun (it measures
    50–95 m up). Unchased it takes 61–91 s to reach the edge.
  - Within `sunCrystalEdge` 40 m of a wall it fades (`pu.fade` 1 → 0 over
    2.5 s, still drifting; it's gone about 30 m inside the wall). Eaten or
    faded, the next of its flavour is due `sunCrystalRespawn` 4 s ×
    0.75–1.25 later.
  - Bots (`Brain.treasure`) skip a sun crystal within `botSunGap` 60 m of
    the sun. Body heat is only a reward (more speed and thrust), so nothing
    else keeps them away: without the gap 25 bots keep about 9 within 50 m
    of the sun and eat 30 sun crystals a minute at a median 26–30 m from
    it; with it about 2–3 (the same as with the rule off) and 11–14 a minute
    at a median 70 m.
  - The renderer gives each an ink ring (a sprite over everything: a rim of
    its colour inside a dark band, so it reads on the sun's glare where an
    additive glow can't), shown from 20–45 m out and kept at least 5% of
    the screen; it flickers white while hatching. It leaves a trail of 24
    sparks a second (12 on Low) and shrinks as it fades. A birth flares
    (`sunFlare`): a ring of its colour grows to 46 m round the sun in 1.1 s,
    with 60 sparks, and a soft three-note chime (`Audio.sunCrystal`) within
    220 m of the sun. The radar gives it a gold ring.
- **Flaming pearls** (`updatePearls`, rule `pearls` 3, at most 8):
  - They spawn 0.2–0.65R from the centre (squashed like the food cloud in
    Skyhold) and at least 40 m from any wall.
  - They drift with the same wander as power-ups at `pearlDrift` 2.5 m/s
    (×0.6–1.4), re-aiming every 8–16 s with τ 4 s, and turn home past 0.7R:
    long, sweeping curves.
  - A head within 3 m + r catches one: +`pearlMass` 30 (half for bots above
    mass 400) and a `pearl` event. A new pearl is due `pearlRespawn` 8 s
    (±25%) later, at the farthest of 6 candidates from the catch.
- **Dragonfire** (`updateBreath`, `fireTarget`, `breathStats`):
  - Each fire crystal adds a charge, up to `fireChargeMax` 5 (rule
    `fireCharge`; with it off a crystal sets one charge). One breath spends
    them all: `d.breathLevel` = the charges spent.
  - `breathStats(lv)`, with k = lv − 1 (capped, 0 with the rule off):
    range 24·(1 + 0.25k) m, half-angle 30°·(1 + 0.15k), time 1.2·(1 + 0.25k)
    s, cuts 1 + ⌊0.5k⌋. So level 1 is 24 m, 30°, 1.2 s and 1 cut; level 5 is
    48 m, 48°, 2.4 s and 3 cuts.
  - It hits the nearest enemy bead with index ≥ 3, so it never hits a head.
    Each dragon is cut at most once per breath (`d.breathHits`).
  - After its last cut it trims the rest of the breath to 0.25 s. Each cut
    calls `sever`.
  - Bots (`Brain.fireReady`) breathe when a tail is in the cone and they hold
    1 + (hunter or kingslayer) + (mass > 150) + (aggr > 0.6) charges, capped
    at the max.
- **Breath elements** (rule `elements`; `ELEMENTS` = fire, ice, bolt, acid):
  - Charges are shared. A breath crystal sets `d.element` to its type, so the
    last one eaten decides; `d.breathEl` is the element of the breath in
    progress. With the rule off, or for a browser that only knows fire
    (`d.fireOnly`, §4.3), it is always fire.
  - Each scales with `breathStats`: `ts` = 1 + 0.25k (time) and `rs` =
    1 + 0.25k (size).
  - **Ice** (`frost`): the fire cone, for the full breath time. Every dragon
    with its head or any bead in it gets `chill` = `chillTime` 2.5 s × ts.
    While chilled (`move`): no boost, turn rate × `chillTurn` 0.6, target
    speed × `chillSpeed` 0.5, applied at once.
  - **Lightning** (`strike`): crackles for half the breath time until
    `nearestPart` finds a head or bead within `boltRange` 1.5 × range, inside
    a `boltAngle` 7° × (angle/30°) cone. Then it jumps to the nearest unstruck
    dragon within `boltChain` 14 m, min(`boltChainMax` 3, 1 + ⌊k/2⌋) times.
    Each struck dragon gets `stun` = `stunTime` 0.6 s × ts (stick and boost
    dead, wall assist on) and sheds max(2, `boltShed` 4% × ts of its mass);
    80% of that drops as food where it was struck.
  - **Acid** (`spitAcid`, `updateClouds`): a cloud (`world.clouds`, at most 12)
    of radius `acidRadius` 6 m × rs, lasting `acidTime` 6 s × ts, spat 2r + its
    radius ahead at speed + 10 m/s and slowing with τ 0.5 s. Each tick any
    other dragon with its head or every other bead within radius + r/2 loses
    `acidRate` 4 × ts mass/s, never below spawn mass. 80% drops as 1.5-orbs
    where it touches. The spitter is immune. `acid` events are rate-limited to
    one per victim per 1.5 s.
  - Spawn protection blocks every element; the shield doesn't (as with fire).
  - `status` counts `chill` and `stun` down every step (in `client` mode,
    for your own dragon, between snapshots).
  - Bots (`Brain.breathTarget`): ice and lightning when their target is their
    prey, bigger, or heading at them. Acid when a dragon's path meets the
    cloud's path within 1.5 s, or one is within 25 m on their tail. Their
    feelers treat other dragons' clouds as hazards (`World.inAcid`).

### 3.5 Rules layer and tunables
- **`World.rule(k)`** returns `world.rules[k] ?? T[k]` (`sim.js:325`). Every newer
  mechanic reads through it, so a room can override it:

| Rule | Default | Rule | Default |
|---|---|---|---|
| `tailBite` | 1 | `aggrStart` | 0.25 |
| `biteBeads` | 5 | `aggrRampMin` | 15 |
| `biteMult` | 5 | `botAggrMax` | 1 (0.5 in every real game) |
| `lives` | 3 | `perks` | 1 |
| `respawnDelay` | 3 | `lengthSpeed` | 0.5 |
| `botMoods` | 1 | `lengthSpeedExp` | 0.62 |
| `fireCharge` | 1 | `lengthSpeedMax` | 3 |
| `fireChargeMax` | 5 | `elements` | 1 |
| `speedCap` | 4 | `lengthSpeedLate` | 1.35 |
| `powerupDrift` | 1 | `botTreasure` | 1 |
| `botTreasureNear` | 18 | `botTreasureFar` | 150 |
| `pearls` | 3 | `pearlMass` | 30 |
| `pearlRespawn` | 8 | `pearlDrift` | 2.5 |
| `girth` | 1 | `girthExp` | 0.585 |
| `sunCrystals` | 1 | `sunCrystalSpeed` | 4 |
| `sunCrystalHatch` | 1.5 | `sunCrystalEdge` | 40 |
| `sunCrystalRespawn` | 4 | `botSunGap` | 60 |

- **Beginner rules:** solo (`main.js:453`) and every room (`rooms.js:27,100`) apply
  `BEGINNER_RULES = {botAggrMax: 0.5}`.
- **Not in the rules layer:** `powerups`, `dragonfire` and `botAggression` are
  read straight from `T`, so a room can't override them.
- **`T` is one shared object.**
  - Solo applies local overrides from `wyrm.tune.v2`, but only when the dev
    panel is enabled (`?dev=1` or a localhost page). Otherwise they are
    ignored and left in place.
  - Online, the server's `T` and rules replace it on `welcome` (`net.js:60-75`).
    Your own `T` is kept aside on join and put back when you leave.
  - The server can be retuned with the `WYRM_TUNE` JSON environment variable.
  - The full list is in Appendix A.

### 3.6 Bots (`site/js/bots.js`)
- **Thinking:** each bot thinks every 0.08–0.16 s, depending on its skill
  (0.6–1.0).
- **Avoidance** probes the nose, the midpoint, the goal and 16 feelers on two
  cones (30° and 65°). The look distance is (7 + 0.55·speed)·(0.8 + 0.3·skill).
- **Pull-out guard** (gravity worlds): a bot diving lower than it can level
  out from, turn radius × (1 − cos dive) + 0.3 s of travel + r + 8 m, climbs
  instead, and brakes below 60% of that. Without it, ×4 bots fly into the
  cloud sea.
- **Moods** (`bots.js:17-38`):
  - Grazer (hunt 0), sunbather (0.8), hunter (1.6), kingslayer (1).
  - Mood weights shift toward hunters and kingslayers as aggression A rises:
    [0.4−0.25A, 0.4, 0.12+0.4A, 0.03+0.17A].
- **Aggression:** A = min(`botAggrMax`, a0 + (1−a0)·min(1, age/(15 min))).
  - Age counts from when the room last woke (`world.ageStart`).
  - With the 0.5 cap, A tops out after about 5 min.
- **Population:** target = min(30, 3 + ⌊t/20 s⌋), minus humans online.
  - Extra bots retire farthest from the player first.
  - The menu's attract mode uses 30.
- **Gentle period:** in solo, during your first 3 runs, bots ignore you for 45 s
  after you spawn (`main.js:136`).
- **Treasure** (`Brain.treasure`, rule `botTreasure`): checked after a
  grazer's flee and before stalking or feeding. Drive = (length − 12)/188,
  from 0 for a hatchling to 1 from 200 m:
  - Notice range: `botTreasureNear` + (`botTreasureFar` − near)·drive, ×(0.5 + A).
    Per decision a bot looks with chance 0.2 + 0.6·drive, best by 1/(dist + 10),
    halved if behind. It skips breath crystals (fire, ice, lightning, acid)
    once its charges are full (`fireChargeMax`, or 1 with `fireCharge` off),
    and sun crystals still within `botSunGap` 60 m of the sun (§3.4).
  - Commitment: holds the goal 1.5 + 8·drive s, and drops it early with
    chance 0.05·(1 − drive) per decision.
  - Path: drive > 0.3 leads the crystal's drift; smaller bots wobble up to
    0.5·(1 − drive) off the line. Above drive 0.5 a bot may boost when
    another dragon is closer to it. The feelers still decide the final
    direction.
  - Fair play: below A 0.75 (every beginner room) a bot skips a crystal if a
    human is within (1.75 − A)× its own distance.
  - Pearls count 2.5× a crystal and are noticed from 1.3× as far.
- **Names:** 44 dragon-style names, deduplicated.

## 4. Multiplayer

### 4.1 Who decides what
- **The server is the authority for:**
  - bots
  - collisions, deaths, bites and sever
  - food and growth
  - power-ups, and what every breath does (cuts, chills, stuns, acid)
  - heat and thrust
- **The client is trusted for:** its own pose.
  - It flies its dragon locally and sends a pose 30 times a second.
  - The server's `World.applyNet` (`sim.js:532-561`) keeps a movement budget:
    - top = (boost or cruise speed)·speedX + dive + 1, up to 111 m/s at ×4
    - refills at top·dt·1.15
    - capped at half a second's worth
  - Anything beyond the budget is clamped, and `me.c` tells the client to
    hard-snap back (`net.js:154`).
  - **Chill and stun are enforced here too**, `NET_GRACE` 0.25 s after they
    start (while the news is in flight):
    - chilled: no boost, and top is × `chillSpeed`
    - stunned: no boost or brake; only progress along the old heading is
      kept and the reported quaternion is ignored (a sideways claim > 1 m is
      corrected), unless `wallAhead` says the straight line meets a wall
      within the assist's look-ahead, where the browser's wall assist may
      steer.
  - Bank is clamped to ±1.2. A quaternion is accepted only if its length² > 0.5.
    The reported speed is clamped to 150 m/s, then to top.
- **Other dragons** are drawn on the server's clock (`net.js` `ServerClock`,
  `poseAt`, `update`):
  - Each snapshot is placed at its `tm`, put back on the 1/30 s tick.
  - Server "now" is local time minus the smallest arrival lag of the last
    2 s, eased over about 1 s. It jumps if the server is more than 0.25 s
    ahead, and starts over if `tm` goes back (a restarted room).
  - Dragons are drawn 120 ms behind that, blended between the snapshots
    either side. Past the newest, they carry on from the last two for at
    most 120 ms, then hold. After a stall the draw time waits at that edge
    and the delay is learned afresh, so dragons carry on from where they
    stopped instead of jumping ahead.
  - Tails are laid through every snapshot passed, never along a guess, so
    the drawn tail keeps to the server's.
- **There is no client prediction or reconciliation** beyond that snap.

| Item | Value |
|---|---|
| Server tick | 30 Hz, from a 60 Hz `setInterval` with an accumulator capped at 0.25 s |
| Snapshots | 15 Hz (`SNAP_EVERY = 2`) |

### 4.3 Wire protocol
- The protocol is JSON text frames only. A binary frame closes the socket.
- Positions are rounded to 2 decimal places and quaternions to 3.

| Direction | Message | Contents |
|---|---|---|
| C→S | `hello` | `{name, perks[], skin, caps[], resume?}`. Must be the first message, within 5 s. `caps` (optional, up to 8 short strings) says what the browser understands: `el` = breath elements. `resume`: the token from the last `welcome`, when reconnecting (§4.4) |
| C→S | `p` | `{x,y,z,qx,qy,qz,qw,s,bk,b,k,f}`: pose, speed, bank, boost, brake, fire |
| C→S | `spawn`, `park`, `unpark`, `ping{c}` | |
| S→C | `welcome` | `{you, room, tune, rules, time, dragons[meta], orbs[flat×7], pu, pl}`. Also `resume` (a new token every time), `resumed: 1` when a `hello`'s token got its dragon back, `parked: 1` when that dragon is still folded (not in `dragons`) |
| S→C | `s` (snapshot) | `tm`. `d`: `[id,x,y,z,qx,qy,qz,qw,mass,len,flags,bank,speed]` per dragon. `o`: food changes. `pu`: power-ups, `[type,x,y,z,spin]` each; a sun crystal adds `id, fade, hatch` (optional; new): older clients read the first five and see it as a crystal (as fire without `el`), and new ones keep it by `id` and draw it on the server's clock like a pearl. `pl`: pearls, `[id,x,y,z]` each (optional; new). `lb`: top 10. `n`, `h`: counts. `me`: your own heat, thrust, fire (stored charges; older clients only test it for truthiness), `bl` (the breath's level), `el` (their element, when not fire), `ch` / `st` (s left chilled / stunned, when > 0), shield, magnet, kills and correction. `ac` (when any): acid clouds `[id,x,y,z,radius,s left,lifetime,spitter]` |
| S→C | `dn` / `dx` | A dragon appears (meta plus a tail path at 1 cm precision, every other point, ≤600 points) / leaves |
| S→C | `e` | Events: `death`, `sever`, `fire` (`lv`: charges spent, `el`: element), `chill` (`o`, `t` s), `bolt` (`o`: ids struck, `p`: points mouth→hits, `s`: stun s), `acid` (`o`), `pearl` (`{id, g, x, y, z}`; new), `sun` (a sun crystal is born: `{kind, id, x, y, z}`; new, older clients skip it), `bite`, `land`. Also personal events: `eat`, `tier`, `nm`, `pu` (`n`: charges now held), `shield`, `miss` (`el`), `empty`, `park*` |
| S→C | `full` | The room is full |

- **Flag bits** in `d`:

| Bit | Meaning | Bit | Meaning |
|---|---|---|---|
| 1 | alive | 32 | breath |
| 2 | boost | 64 | human |
| 4 | brake | 128 | bot |
| 8 | protect | 256 | magnet |
| 16 | shield | 512 | chilled |
| | | 1024 | stunned |

- **WebSocket close codes:**

| Code | Reason |
|---|---|
| 1011 | room error: the room hit an exception and was reset, or this socket's message threw (§4.4) |
| 4000 | no hello within 5 s |
| 4002 | more than 5 bad messages |
| 4003 | room full |
| 4008 | rate limit or binary frame |
| 4009 | too slow: more than 4 MB queued for the socket (§4.6) |
| 4010 | server restarting (SIGTERM, a deploy): reconnect now |
| 4011 | replaced: the same resume token connected again (§4.4) |

- **Codes the browser sends:** 1000 when the player leaves a room; 4001 when
  it gives up on a socket that went silent and means to come back. Older pages
  close with no code, which the server sees as 1005.
- **Reconnect** (`net.js`): any close other than 4000, 4002, 4003 or 4008
  retries after 0.5, 1, 2, 4 and 8 s, then every 8 s, for 30 s in all. Each
  `hello` carries the resume token. A socket with nothing heard for 6 s is
  dropped. A retry that can't connect checks `/api/rooms` and stops if the
  room has gone. Against a server without tokens it simply rejoins with a
  fresh dragon.

- **Compatibility rule.**
  - The site (GitHub Pages) and the server (Cloud Run) deploy separately, and
    phones cache the site.
  - So any protocol change must accept the previous message shape for at
    least one release.
  - There is no version field. Newer browsers list what they understand in
    `hello.caps`.
  - Older browsers ignore event kinds, flag bits, `me` fields and snapshot
    fields they don't know. Their renderer would throw on an unknown crystal
    type, though, so a browser without `el` is sent `ice`, `bolt` and `acid`
    crystals (in `pu` lists and its own `pu` events) as `fire`. Its dragon
    breathes fire whatever it eats (`d.fireOnly`). It is still chilled and
    stunned like everyone else, enforced by the server's budget, which it
    feels as corrections.
  - A newer browser on an older server treats rules the server's `tune`
    lacks (`fireCharge`, `elements`, `girth`) as off.
  - **Girth** changes hitboxes, and a browser works out every radius
    itself from mass and the room's rules (snapshots carry mass, not
    radius). So for one release, a page cached from before the rule draws
    every dragon thinner than the server's hitboxes (and sizes its own wall
    assist and camera thin): a fat tail can kill a little outside what that
    page shows. It goes away when the cache refreshes.
  - **Pearls** use only additions that old clients skip, so they need no
    cap: the `pl` field (their `welcome` and `s` handlers read named fields
    only) and the `pearl` event (their event switch has no default). Pearls
    are never put in `pu`. A new client on an old server gets no `pl` and
    shows no pearls.
  - Old pages on this server: they never send `resume`, so they always get a
    fresh dragon, and they ignore the new `welcome` fields and close codes.

### 4.4 Rooms (`server/rooms.js`)
- **Defaults:** `the-orb` ("The Orb", orb) and `skyhold` ("Skyhold", sky).
  Both are permanent and beginner.
- **Names of created rooms** are generated, never typed: an adjective and a
  noun from the lists in `names.js` (24 × 24, e.g. "Jade Peak"), checked
  with `isRoomName`. The names test checks that every pair passes the room
  filter against the reserved names (`RESERVED_ROOM_NAMES`: The Orb,
  Skyhold, Skyhold Nest, Skyhold (Beginners), Skyhold Beginners, Nest and
  Orb, plus the reserved words in `names.js`) and that no word contains one.
- **Limits:**

| Item | Value |
|---|---|
| Humans per room | 30 |
| Bots per room | fill to 30 − humans |
| User rooms at once | 30 (503 when full) |
| Room creations per IP | 3 per hour (429), counted in memory |

- **Create** (`POST /api/rooms`):
  - Requires an allowed origin, JSON content and a body of at most 1 KB.
  - Then checks, in order: the per-IP rate limit and the global cap.
  - The name is the `name` asked for if it's a list name not in use;
    anything else (a taken name, or free text from an old cached client)
    gets a random unused list name. The name never fails a create.
  - The `beginner` field is ignored, so every room is a beginner room.
  - The room id is 9 random bytes in base64url: 12 characters, about 72 bits.
- **Lifecycle:**
  - A room's world is created on its first join, with a 10 s warm-up run before
    players arrive (`rooms.js:106`). It is freed after 10 min empty.
  - Expiry: `expireAt` is set to now + 12 h when a room is created or becomes
    empty, and cleared while anyone is in it. Expired rooms are hidden and then
    swept.
  - On start, saved rooms whose names aren't list names (typed before names
    were generated) are dropped and deleted from the store.
- **Join:** caps the room's humans, then runs `safePlayerName`, `cleanPerks`
  and `skinById`. It spawns at mass 10, sends `welcome` and broadcasts `dn`.
  A `hello` whose `resume` token matches a held seat gets that dragon back
  instead (below).
- **Leave** (a socket closes): a dragon in the sky stays there for the 3 s
  park countdown, still hittable, so disconnecting never dodges a kill. A
  dragon killed meanwhile drops its loot once, as any death does. Then:
  - **Left on purpose** (close 1000 or 1005) or sent away (4002, 4008): it
    drops 80% as loot and `dx` goes out.
  - **Dropped** (any other close): it folds away like park (`land`, `dx`),
    keeping its mass and kills, and its seat is held for 30 s under the
    player's resume token.
  - A dropped player's parked dragon is held as it is. A dead one is just
    removed.
- **Resume tokens** (`Room.held`): 16 random bytes, base64url. In memory
  only, never logged, one room only, single use (every `welcome` brings a
  new one), forgotten 30 s after the dragon folds. With a held token:
  - within the 3 s the dragon simply carries on, and others never see it go;
  - after that it flies back in like unpark (a safe spot, spawn protection,
    `dn`) but keeping its crystal element and dragonfire charges, or stays
    folded if the player had folded it;
  - if the old socket is still open (the browser noticed the drop first), the
    new one takes the dragon over and the old one is closed with 4011.
  - Held seats count as humans: the room keeps ticking and keeps their place,
    and bots fill around them.
  - Each `hello`, a resume's too, carries `caps`, so what the new connection
    is sent (and `d.fireOnly`) follows the browser now playing.
- **Respawn:** refused while alive, while parked, or within 1 s of a death. The
  server doesn't enforce lives; the client counts them.
- **Park** (online pause, `rooms.js:188-226`):
  - A 3 s countdown during which you are still hittable, then you are removed
    with your mass and kills kept.
  - You can unpark after 2 s, and you return at a safe spawn point with
    protection.
- **Per-room `meta.rules`:** merged in at `rooms.js:100` but never set. The
  hook exists for future modes.
- **Errors:** each room's tick and sweep run in a try/catch
  (`Registry.guard`), and so does every WebSocket message and leave.
  - An exception is logged with its stack. The same error is logged at most
    once a minute, and the sweep reports how often it repeated.
  - In a tick or sweep, only that room is reset (`Room.reset`): its lives are
    counted as disconnects, its sockets close with 1011 and its world is
    freed. The other rooms carry on.
  - In a message (or a leave), only the socket that sent it is closed (1011);
    its room carries on, so one crafted message can't throw everyone out.
  - An unhandled promise rejection is logged the same way, not fatal.

### 4.5 Persistence (`server/store.js`)
- **Which store:**
  - Firestore when `STORE=firestore`, or on Cloud Run unless `STORE=memory`.
  - Otherwise an in-memory Map.
- **What is stored:**
  - The room list, in the `rooms` collection:
    `{id, name, arena, beginner, permanent, createdAt, expireAt}`.
  - The anonymous daily play and visit totals (§4.7, §4.8), in the `stats` collection: one
    document per UTC day, id `YYYY-MM-DD`. The server keeps 30 days and
    deletes older ones, so the collection stays at about 30 small documents.
- **Game state** is held in memory only. A restart drops every dragon.
- **Writes are fire-and-forget.** Errors are logged and ignored.
- **Totals:** the current day is written at most once a minute, only when it
  changed, and again on SIGTERM. Recent days are loaded on boot, so a restart
  or deploy doesn't zero the day.
- An optional Firestore TTL policy on `expireAt` can act as a backstop.

### 4.6 Endpoints and limits (`server/server.js`)

| Endpoint | Notes |
|---|---|
| `GET /healthz` | `ok` |
| `GET /api/rooms` | The room list. CORS headers are sent only for allowed origins |
| `POST /api/rooms` | §4.4 |
| `POST /api/run` | One solo life's anonymous numbers (§4.7). 204, or 400 / 403 / 413 / 415 / 429 |
| `POST /api/visit` | One page visit's anonymous note (§4.8). 204, or 400 / 403 / 413 / 415 / 429 |
| `GET /api/stats` | The public daily totals, newest day first. `Cache-Control: public, max-age=60` |
| `OPTIONS` | 204 for an allowed origin, else 403 |
| `WS /ws?room=<id>` | Checks path, origin, room and the per-IP cap |

- **Origin allowlist:**
  - `ALLOWED_ORIGINS` defaults to `https://skywyrm.io,https://www.skywyrm.io`.
  - Off Cloud Run, or with `ALLOW_LOCALHOST=1`, any localhost or 127.0.0.1 port
    is also allowed.
  - A missing Origin header is accepted only in dev.
- **Client IP:** the last `X-Forwarded-For` entry. It is held only in
  memory, for the per-IP limits below, and never stored or logged.
- **Limits:**
  - 16 sockets per IP (429 beyond that), so a family or a classroom on one
    network can play together. `MAX_CONN_PER_IP` overrides it; anything but
    a positive whole number falls back to 16. Seats held for that IP's
    dropped players (§4.4) count toward it (`Registry.heldBy`).
  - 20 run notes per IP per hour (`POST /api/run`) and, counted apart, 30
    visit notes (`POST /api/visit`), in memory and swept every minute. The
    body is at most 512 bytes.
  - 2 KB maximum frame.
  - A token bucket of 90 messages burst, refilling at 60 per second.
  - Backpressure (`server/client.js`): while more than 512 KB is queued for
    a socket, snapshots are skipped, and their food changes ride along with
    the next snapshot that goes out. Every other frame (`welcome`, `dn`,
    `dx`, `e`, `pong`) always goes out. A socket more than 4 MB behind is
    closed with 4009.
- **Response headers:** `no-store` (except `/api/stats`), `nosniff`, `Vary: Origin`.
- **Server-side checks on what clients send:**
  - Names go through `names.js`.
  - Perks and skins must be known ids, with at most 2 perks. The rank that
    unlocks them is *not* checked.
- **`?server=` override:** honoured only on a localhost page, and only for
  localhost or `*.run.app` targets (`net-config.js:8-15`).

### 4.7 Play totals (`server/stats.js`)
The improvement loop's numbers, kept without identifying anyone
([privacy.html](../site/privacy.html), PRD §11).
- **What a life reports:** world (`sky`/`orb`), peak length (m), seconds
  flown, kills, and how it ended: `wall` (any arena edge, including the cloud
  sea), `body` (a tail), `headon`, `quit`, `disconnect` or `other`. Dragonfire
  and heat don't kill, so they have no cause yet; a new cause counts as
  `other` until it is added.
- **Solo:** at the end of each solo life (`main.js` `reportLife`, next to
  `bankLife`, and when you leave to the menu), the browser sends one note:
  `fetch(serverUrl() + '/api/run', {method: 'POST', keepalive: true})` with a
  `text/plain` body `{v: 1, mode: 'solo', arena, len, secs, kills, cause}`.
  Text/plain keeps it a simple CORS request (no preflight). There is no id,
  cookie or name, and every failure is ignored. It is skipped when
  `SERVER_URL` is `''` and never sent for online lives.
- **Checks:** allowed origin, `text/plain` or JSON, at most 512 bytes, the
  per-IP limit, then `cleanRun`: `v` must be 1, `mode` `'solo'`, `arena` a
  known world, and the numbers finite. Numbers are clamped and rounded (length
  0–2000, seconds 0–7200, kills 0–500). An unknown cause becomes `other`.
  Other fields are dropped.
- **Rooms:** the server counts its own humans' lives (`Room.startLife` and
  `endLife`). A life ends on a death, on leaving with the dragon still flying
  or parked (close code 1000, 1001 or 1005 is `quit`; anything else is
  `disconnect`), or on SIGTERM (`disconnect`). Time parked is left out, and
  the peak length survives a park.
  - A dropped connection's seat (§4.4) is not an ended life: the life moves
    with the seat and carries on if the player reconnects. It is counted when
    the dragon dies in its 3 s countdown, when the seat is forgotten after
    30 s (with the leave's cause), or on SIGTERM. A player who left on purpose
    or was sent away is counted as they leave.
- **Per day and source** (`solo`, `room`): `runs`, `secs`, `kills`, `maxLen`,
  a peak-length histogram (`0-15`, `15-25`, `25-50`, `50-100`, `100-200`,
  `200+` m; a new dragon is 12 m), counts by `cause` and by `arena`. Plus, per
  day: `peakHumans` (all rooms at once, checked on each join and every minute)
  and `roomsCreated`.
- **Compatibility:** an older server answers `/api/run` with 404, which the
  page ignores. Older pages send nothing, and their room lives are still
  counted. The WebSocket protocol is unchanged.

### 4.8 Visit totals (`site/js/visit.js`, `server/stats.js`)
Growth numbers (how many people come, from where, whether they come back,
where they drop off), kept without identifying anyone
([privacy.html](../site/privacy.html), PRD §11).
- **When:** one note per page load, when the visit ends: the first
  `visibilitychange` to hidden or `pagehide`, whichever comes first, and
  never again for that page (a page restored from the back/forward cache
  sends nothing more). So a visit that switches tabs and comes back is
  reported as it was when it first hid.
- **How:** `fetch(serverUrl() + '/api/visit', {method: 'POST', keepalive:
  true, credentials: 'omit', referrerPolicy: 'no-referrer'})` with a
  `text/plain` body (no preflight). Skipped when `SERVER_URL` is `''`; every
  failure is ignored.
- **The note:** `{v: 1, src, tag, ret, today, dev, stage, lives, secs, invited}`,
  all worked out on the device (`main.js` creates a `Visit` and reports
  starts, lives and play time to it):
  - `src`: `document.referrer`'s hostname reduced to `direct` (none,
    skywyrm.io, or the page's own host), `search`, `social`, `video`,
    `games` or `other` (`visitSource`; the host lists are in visit.js). The
    referrer itself never leaves the device.
  - `tag`: the `?src=` parameter if it is in `VISIT_TAGS` (invite, share,
    qr, reddit, hn, ph, itch, iogames, youtube, tiktok, discord, school,
    club, family, test), else left out. It is taken out of the address bar
    at load (`history.replaceState`); every other parameter and the
    fragment stay exactly as written (`withoutParam`).
  - `ret`: days since this device's first visit, from
    `wyrm.visit.v1 = {first, last}` (UTC days, §5.5): `new` (no record),
    `d0`, `d1`, `d2-6`, `d7`, `d8-29`, `d30+`, or `old` (no record, but
    `wyrm.settings.v1` runs or `wyrm.profile.v1` lives or games show this
    browser played before). The dates are never sent. With storage blocked:
    `new`.
  - `today`: the last visit's day isn't today, i.e. this device's first
    visit today (always true for `new`, `old` and blocked storage).
  - `dev`: `touch` or `mouse` (`Input.isTouch` when the note is sent).
  - `stage`: the furthest of `menu` (the game loaded), `play` (a solo game
    or a room's first life started), `life` (a life finished: a death,
    leaving to the menu, or leaving a room with a dragon), `again` (a second
    life or game started: a respawn, Play again, or another room) and
    `online` (joined a room). The order is fixed, so a visit that joined a
    room counts as reaching `life` and `again` too.
  - `lives`: lives finished (0–50). `secs`: seconds in the `play` state,
    so not paused, dead, hidden or at the menu (0–7200). `invited`: an
    invite link was shared, copied, or copied by hand from its field (§5.6).
- **Checks:** as for run notes (allowed origin, `text/plain` or JSON, at most
  512 bytes, the per-IP limit), then `cleanVisit`: `v` must be 1. An unknown
  `src` becomes `other`; an unknown `tag`, `ret` or `dev` is left out; an
  unknown `stage` counts as `menu`; `lives` and `secs` are clamped and
  rounded (a non-number is 0); `today` and `invited` count only if `true`.
  Every other field is dropped.
- **Per day** (`visit` in the day record): `visits`, `devices` (notes with
  `today`), counts by `src`, `tag`, `ret` and `dev`, `reached` (the funnel,
  cumulative: `reached.play` counts every visit at `play` or later), a
  `secs` histogram (`0`, `<1m`, `1-5m`, `5-15m`, `15-30m`, `30-60m`,
  `60m+`), `lives` (their sum) and `invited`. Each field bumps only its own
  counter and the note is then forgotten, so no combination of one visit's
  answers is ever stored.
- **Reading them:**
  - `devices` estimates the day's devices (a browser with storage blocked
    counts every visit).
  - `ret` counts devices, not visits: the page sends its return bucket
    only with the device's first visit of the day. So `ret.new` is the
    day's new devices, and `ret.d1` on the next day over `ret.new`
    estimates the D1 return rate (D7 likewise with `d7` seven days on).
  - The funnel: `reached.play / reached.menu` is how many visits start
    playing, and so on down.
- **Compatibility:** days saved before visits were counted load with every
  visit counter at 0 (`fromStored`), and `/api/stats` only gained the
  `visit` field. An older server answers `/api/visit` with 404, which the
  page ignores.

## 5. Client

### 5.1 Boot and loop (`main.js`)
1. **`carryOver()`** imports a `#carry=` fragment (base64url JSON `{p, s}`) into
   `wyrm.profile.v1` and `wyrm.settings.v1`, but only when those are empty. It
   then strips the fragment. This was built for the move from dendroslabs.com;
   that page is gone now, so this code can be removed.
2. **Load the profile and settings.** `settings.beginner` is forced to true.
3. **Build the attract world:** 30 bots, warmed up with 25 s of simulation.
4. **Each frame:**
   - Inside a try/catch (the crash guard):
     - input
     - sim (solo) or net (online)
     - camera
     - HUD at 4 Hz for the leaderboard
     - render
     - audio
   - If a frame throws, it is recorded, and the next `requestAnimationFrame` still
     runs.
5. **Lives:** counted in `main.js:76-104,223-273`. `bankLife` turns each life into
   jade, and `reportLife` sends a solo life's anonymous numbers (§4.7).
   `visit` (a `Visit`, visit.js) is told when a life starts and ends and
   how long you fly, and sends the visit note when the page first hides
   (§4.8).
6. **Hidden tab** (`visibilitychange`): solo pauses, and online play folds your
   wings like Esc (`park`, with the server's 3 s countdown). Coming back shows
   the pause screen, and Resume flies back in. A hidden tab doesn't run the
   loop, so `NetGame` queues only your own deaths and bites and the park
   events while hidden (or once 200 are waiting), and drops the rest.

### 5.2 Robustness
- **Crash guard** (`main.js:607-646`):
  - `noteProblem(kind, err)` stores the last problem in `wyrm.crash.v1`:
    `{kind, msg, at, state, online, ua}`.
  - It shows a toast at most once every 10 s.
  - It catches `error`, `unhandledrejection`, per-frame exceptions and WebGL
    context loss.
  - Settings → Player → **Last problem** shows it, with Copy and Clear buttons.
- **WebGL context loss:** the game calls `preventDefault`. On restore it forces
  Low quality and rebuilds the reflection map (`Renderer.restore`), which only
  ever lived on the GPU. A loss that comes back within 5 s is noted quietly,
  with no crash toast.
- **Reconnect** (`net.js`, `main.js` `onDrop`/`onRejoin`):
  - When an online connection drops with a dragon to keep (flying or
    folded), the picture holds still with a "Reconnecting…" line in the
    message stack (on the pause panel, if paused) and the client retries (§4.3).
  - If you were dead, it waits and reconnects when your next life starts.
  - Back in, the world (and the `ServerClock` timeline) is rebuilt from the
    new `welcome`. A resumed dragon keeps its object and this life's stats.
    A hidden tab has already folded its wings, so a drop while hidden comes
    back folded. Otherwise the lost life is banked
    and a toast says "Server updated — new life" (after a 4010) or
    "Reconnected — new life".
  - The client re-sends what it is doing: `unpark` when flying, `park` when
    paused.
  - After 30 s it gives up as before: the menu, with "Disconnected from the
    server".
  - Leaving a room (or giving up) banks the life you had there (`endLife`).
- **Cache stamps:**
  - Every module import and stylesheet link carries `?v=N`.
  - When a file changes, its stamp must be bumped in *every* file that references it.
  - `scripts/check-stamps.mjs` enforces this in CI.
  - The voice clips are fetched without a stamp, so a re-render goes in a
    new folder (`audio/voice/v2/`, `CLIPS` in `voice.js`).

### 5.3 Input, camera, HUD
- **Input** (`input.js`):
  - Mouse: offset from the screen centre inside a circle `mouseCircle` 0.36
    × the shorter screen side, with deadzone 0.06. Past the deadzone,
    `u` runs 0 → 1 to the rim and `mouseStick` gives u ÷ ((1/a − 2)(1 − u) + 1),
    an expo curve that is `a` half way out and 1 at the rim, with
    a = `mouseHalf` 0.25 × Mouse sensitivity (Settings → Player, 0.4–1.6,
    saved with the settings): u ÷ (3 − 2u) at 1.0. Then a little smoothing
    (`smoothMouse`, on wall time): a change eases in over
    `mouseSmooth` 0.06 s ÷ (1 + change ÷ `mouseSmoothGap` 0.1), so a ±3 px
    wobble at 10 Hz moves the stick a third as much, and a full swing gets
    90% of the way in one frame. The sim's own `steerTau` smoothing comes
    after, for every input.

    | Mouse offset (share of the old 0.30 circle) | 5% | 15% | 30% | 60% | 100% | 120% |
    |---|---|---|---|---|---|---|
    | Before: 0.30 circle, power 1.5 | 0 | 0.030 | 0.129 | 0.435 | 1 | 1 |

  - The neutral point re-zeroes at spawn (to a finger held through a

### 5.4 Audio
- **Sound effects** (`audio.js`):
  - All synthesised in WebAudio, with master gain 0.6.
  - **Wind** (`Audio.wind`, every frame): soft noise (pink, kept to about
    140 Hz – 1.3 kHz and looped seamlessly; made once on the first tap)
    through one band-pass, the same three nodes the old white-noise hiss
    used. Speed is heard against the dragon's own cruise speed (`speedX`),
    so a long, fast dragon's air is only a little fuller, not brighter. The
    bed is quiet at cruise (about −37 LUFS) and gusty: a new strength and
    colour every 1.5–4.5 s, drifting there over about a second. Boost, sharp
    turns (`turnRate` in `main.js`) and dives lift the band toward 1 kHz and
    swell it into a whoosh that fades about half a second after. Parameters
    change only when they move by more than 2%: a few times a second at
    cruise, never in the menus. The near-miss and boost whooshes use the
    same soft noise; the crisp effects (bites, frost, lightning, acid) keep
    white noise.
  - The food chime and the pearl's bell run climb a pentatonic ladder in the
    music's current mode (D yu until the music starts).
- **Music** (`music.js`): an original score composed live in Chinese
  pentatonic modes. Home is D yu (D F G A C); sections also visit the shang,
  zhi and gong modes and the A, F, G and C tonics. Nothing loops:
  - A phrase (4 bars) is written at a time from a motif: stated, developed
    (sequence, inversion, retrograde, new rhythm), handed between two voices
    (call and response, echoes or unison) and closed with a cadence, open on
    the 5th and then home. Each phrase starts on the note the last one ended
    on.
  - Sections A (theme), B (contrast), C (lyrical) and X (a two-bar opera
    gong-and-drum break) rotate the lead voice, zheng figure, drum kit and
    key. A new theme replaces the old one every 7 sections. Menu → flying
    starts the theme on the next bar.
  - Instruments: guzheng and ruan (Karplus-Strong strings rendered once and
    replayed at any pitch, with bends, tremolo and glissandi), dizi and xiao
    (breath noise, grace notes, vibrato), erhu (slides, scoops, swelling
    vibrato), sheng chords, and rendered one-shots for dagu, bangu, muyu, two
    cymbals, the big gong (with a reversed-gong swell into sections) and the
    small opera gong. Stingers use suona, zheng, gongs and drums, in the
    current mode; the ice, lightning and acid crystals get short ones,
    quieter than dragonfire's.

| Level | When | Tempo | Instruments |
|---|---|---|---|
| 0 | menu, pause, dead | 80 BPM | sheng, zheng, xiao or erhu, gongs |
| 1 | flying | 108 BPM | adds ruan bass, dagu, bangu or muyu, dizi or erhu |
| 2 | action | 120 BPM | adds dagu fills, cymbals, 16th-note zheng and a second melody voice |

  - `hype()` windows trigger level 2.
  - Level changes land on bar lines and the tempo glides there over about two
    bars. Stingers are quantised to 16ths.
  - Pause adds a 650 Hz low-pass.
  - **Cost:** the instruments render in about 20 jobs of a few ms, one per
    25 ms scheduler tick, after the first tap. Melody notes that touch share
    one oscillator, and at most 28 sources sound at once (accompaniment gives
    way first). It builds about half the audio nodes the old loop did.
- **Voice** (`voice.js`): 8 events × 3 phrases.
  - Delivered like a ring announcer: a lively male voice (Kokoro speaker
    82) at 1.2× speed, with a wider, higher pitch contour, a held last
    syllable, light compression and an EQ matched to shouted speech
    (`notes/voice/README.md`). Clips are −15 LUFS, about 4 dB louder than
    the old ones really were.
  - Priorities: power-up 1 < tier 2 < sever and kill 3 < leader 4 < death 5.
  - A higher-priority line interrupts; others are dropped.
  - The voice ducks the music.
  - Captions show the characters, pinyin and English.
- **Hidden tab** (`Audio.setHidden`): the master and wind gains drop to 0,
  the voice line and hum stop, the music scheduler holds (a throttled
  background timer would play stray notes) and the context is suspended.
  Coming back resumes it from any stopped state, including iOS's
  `interrupted`, and every tap or key retries if that fails.
- **Mute** (`Audio.setMuted`): the speaker button (`#mute-btn`, top left on
  every screen, beside ❚❚ on touch; the start menu sits 23 px lower to clear
  it), M and Settings → Mute all sound share `settings.muted`. The master
  gain ramps to 0 in 20 ms and back to 0.6 on unmute. While muted the music
  scheduler and stingers hold (no notes built for nobody) and a voice line
  in progress stops.

### 5.6 Invite links (`invite.js`, `main.js`)
- **Making one:** the pause panel's **Invite a friend** (shown only in a
  room) and the 🔗 on each lobby row call `invite(room)`. The link is
  `https://skywyrm.io/?room=<id>&src=invite`; on any other host (a local
  test page) it is this page's own address, plus its `?server=` so the
  friend reaches the same test server (`inviteLink`).
- **Sending it:** on a touch device with `navigator.share`, the share sheet
  with `{title: 'Skywyrm', text, url}`; closing the sheet sends nothing. Otherwise
  `navigator.clipboard.writeText(url)` and the notice "Invite link copied"
  (`#notice`, a line at the foot of the screen over the menus, where the
  HUD's messages are hidden or covered). If both fail, the link shows,
  selected, in a read-only field under the button (`.invite-link`). The text
  is "Fly with me in Skywyrm — server {name}", and the name is included
  only if it is a generated list name or a built-in room (`inviteText`), so
  nothing a player typed can get in. Any of these sets the visit's
  `invited` (§4.8). For the share sheet it is set as the sheet opens,
  because picking an app hides the page (which sends the visit note) before
  `share()` returns, and taken back if the sheet is closed.
- **Opening one:** at boot `main.js` reads `?room=`, keeps it only if it
  looks like a room id (`roomParam`: 1–32 of `A-Z a-z 0-9 _ -`) and takes it
  out of the address bar (`withoutParam`; visit.js takes out `src`). It is
  only ever compared with ids from `/api/rooms`, never written into the
  page. When the list arrives, `renderRooms` moves that room to the top
  (`pinRoom`) and marks its row `.pinned` (lit, "You're invited", a larger
  Join), scrolling it into view if needed. Nobody is joined without a tap.
  If the room isn't listed, the notice says "That server has closed — pick
  another" (once) and the list is as usual. The pin goes once you join that
  room, or if it disappears from a later list.
- **Phones:** below 480 px wide the rows are tighter and the player and bot
  counts stack, so the name keeps its room beside 🔗 and Join. On a phone
  on its side the menu's last grid row is `auto`, not `1fr`: the menu's
  max-height capped a `1fr` row, so a long server list spilled out of its
  rows and "more ▾" scrolled up over it.

## 6. Rendering (`site/js/render.js`)

### 6.1 Frame pipeline
1. **Main scene** → `mainRT`: HalfFloat, 4× MSAA on High, linear HDR.
2. **Cube camera:** 6 faces, rendered when wide view or the mirror is on. 768²
   every frame on High. Low has no wide view, and the mirror's 384² cube
   renders every other frame.
3. **Bloom:**
   - Bright-pass at ¼ resolution: threshold 0.85, soft knee.
   - Then two separable 5-tap Gaussian rounds.
   - High only.
4. **Warp pass** to the screen:
   - **Sharp centre:** taken from `mainRT`.
   - **Edges:** the cube is warped with θ(r) = atan(tanHalf·r) + extra·(r/rMax)³, so
     the corners reach `wideCorner` = 122°.
   - **Rear mirror:** an inset rectangle at the top centre.
   - **Bloom:** added before tone mapping, centre only.
   - **Output:** ACES Filmic tone mapping (exposure 1.1), then sRGB encoding.

**Other renderer settings:**
- **Camera:** FOV 72°, near 0.1, far 3000.
- **Pixel ratio:** up to 2 on High, 1 on Low.
- **Wide view default:** on, except on touch devices. A choice made in Settings
  is kept (`wideSet`), and so is an "off" saved before this default existed.
- **Auto quality:** starts on High and drops to Low once if the frame rate stays
  below min(40, ¾ × the screen's rate) for a 5 s window. The screen's rate is
  the median gap between frames 15–90 after load (menu frames, which are
  light), so a 30 Hz screen (iPhone Low Power Mode) drops only below 22 fps.
  The drop is saved (`autoLow`) until Graphics is changed in Settings.

### 6.2 Environment
- **Skyhold:**
  - **Sky:** a camera-following dome at radius 1500, with a low-sun sprite.
  - **Fog:** FogExp2 0xC99A6E at 0.0015.
  - **Cloud sea:** an fbm shader disc that fades into haze.
  - **Karst pillars:** 26, each with pines, merged into one stone mesh and one
    pine mesh (two draws).
  - **Ink-wash ridges:** 3 rings.
  - **Range rings:** at y = 0.3.
  - **Storm wall:** 72 lines plus an additive "qi curtain" cylinder. It
    brightens as you approach (`warn` = clamp((14 − hazardDist)/10)).
- **The Orb:**
  - A nebula dome.
  - A latitude/longitude shell every 20°.
  - 1,500 stars.
  - FogExp2 at 0.0012.
- **Both worlds:**
  - A PMREM environment built from a tiny sky scene, for reflections.
  - A breathing heat sun at the centre: core, halo and corona.
  - Instanced blob shadows.

### 6.3 Dragon bodies: GPU tubes
- **Each body is one continuous tube.** All other dragons share one
  `InstancedBufferGeometry` built from `tubeRing(16, 2)`: 16 sides × 2 rings,
  64 triangles per segment.
- **Interleaved frame buffer:** `InstancedInterleavedBuffer`, stride 18 floats,
  DynamicDraw.
  - Every attribute is read twice, at offset `o` and at `18 + o`.
  - So instance *i* sweeps from spine frame *i* to frame *i+1*, with no seams
    or gaps in turns.

| Floats | Attribute | Meaning |
|---|---|---|
| 0–2 | `aP` | position, including the swim offset |
| 3–5 | `aR` | side axis |
| 6–8 | `aU` | back axis |
| 9 | `aM.x` | radius; **−1 marks a break** between dragons |
| 10 | `aM.y` | distance from the head in units of r |
| 11 | `aM.z` | tier + 8·bloodline |
| 12–14 | `aC` | colour 1, after the tail-tip gold, proximity glow and spawn ghosting |
| 15–17 | `aD` | colour 2 |

- **Spine frames:** rotation-minimising transport of `d.up`.
- **Cross-section:** 1.06 wide × 0.95 tall.
- **Radius profile:**
  - The neck starts at 0.7 and grows over the first 6 beads.
  - The last 15% tapers down to 0.4.
  - With rule `tailBite`, the edible tip (the last `biteBeads` beads)
    narrows to a slender stalk: ×0.62 on its first bead, ×0.42 after.
    Drawing only: the bite hitbox is still r × `tailColScale` round every
    bead, so the tip is easier to bite than it looks, never harder.
  - The last bead is ×0.05.
- **Swim wave** (drawing only; the simulation keeps the true path):
  - Amplitude r·1.05 (×0.6 for your own dragon), wavelength r·14.3, lift 0.35.
  - Phase follows the distance flown.
  - The frame tilts with the wave's slope.
- **Edible tail tip** (rule `tailBite`; every dragon, yours too): besides
  the gold shimmer on others' tips, the stalk carries plume instances (so
  no extra draw): a pair on each edible bead, swept back, (1.1 + 0.25k)·r
  long on the k-th, and at the last bead a tuft of five in a fan (up to
  3r) plus two standing up (2r). They are deep amber gold, pulsing with
  the shimmer (bright enough to bloom on High), flutter a little, and fade
  near the camera on your own dragon. The crest fins stop where the tip
  starts, and the tip's three-fin fan is drawn only with the rule off.
- **Your own dragon:**
  - Drawn in its own tube (1,000 frames), translucent at 0.5 opacity with
    `depthWrite` off.
  - A depth-only pre-pass on the same geometry runs first, so only the
    front surface blends.
  - It shrinks within 3.5 m of the camera.
  - Fins, legs, plumes and the head stay opaque.

### 6.4 Scale shader (`dragonScales`, `render.js:1444-1540`)
- **Scales overlap like roof tiles.**
  - Rows are offset like bricks. The first hit among 3 candidate rows wins,
    so the scale nearer the head lies on top.
  - Each scale has a keel, a crevice shadow under its neighbour, a lip highlight
    and per-scale variation.
- **The bloodline picks the style**, from an FNV-1a hash of the dragon id
  (`render.js:1633`):

| Bloodline | Share of dragons | Scale grid (around × along) |
|---|---|---|
| Scaled | 50% | 13 × 1.9 |
| Feathered | 25% | 15 × 1.15, with quill and barbs |
| Armoured | 25% | 9 × 1.3, broad ridged plates |

- **Colour:**
  - Cream belly scutes with creases.
  - A darker back with slow mottling.
  - A dorsal stripe and some scales in colour 2.
  - An iridescent rim (emissive (1−|n·v|)³·0.3).
- **Relief:**
  - Screen-space derivative bump, with the slope clamped so it doesn't sparkle.
  - Roughness varies from 0.16 to 0.62.
- **Anti-aliasing:** scale edges use `fwidth`. Detail fades out when scales get
  smaller than a pixel (`scaleDetail`), and feather barbs fade to avoid moiré.
- **Tier effects:**
  - Elder+: scale lips are gilded.
  - Ancient: qi veins flow along the body, driven by the `BODY_TIME` uniform.

### 6.5 Heads (`dragonHeadParts`, `render.js:1731-1837`)
- **Parts:** built once from small helpers (`bone`, `lick`, `ruff`), merged per
  material, and shared by every head.
- **Drawn instanced:** one `InstancedMesh` per part (`headDraws`, 21 of them)
  draws that part for every head, so heads cost about 15 draws per scene
  render however many dragons there are.
  - Each head is a rig of sockets (`headFor`): the head, the hinged jaw, the
    two whiskers, the mouth wedge and the pearl. A part is drawn at its
    socket's world matrix; tier decides which parts are drawn.
  - Skin and second colour come from the instance colour (frost-white while
    chilled), and the skin's glow (leader gold, heat, the stun flicker) from a
    per-instance `aGlow`.
  - With no cube map to fill, heads off screen are left out.
  - Head parts keep their indices (`mergedIndexed`): about 6,400 shaded
    vertices a head instead of 24,000, for the same 8,280 triangles.
  - skull, snout, lion nose, brows, cheek frills, a 7-lick ruff
  - eyes with slit pupils, fangs
  - horn buds, deer antlers, a gold crown
  - CatmullRom whiskers, an 11-lick mane, a beard
  - a flaming pearl
- **Head skin:** uses the same scale shader. Antlers and the crown use a gold
  metal on Elder+.
- **Size:** r·(1.45 + 0.05·tier), ×0.85 for your own dragon.

| Tier | Head adds | Body adds |
|---|---|---|
| 0 | buds | fins |
| 1 | antlers | front legs (feathered dragons: plumes every 3rd bead) |
| 2 | mane and beard | back legs, plumes every 6th bead |
| 3 | crown, gold antlers, glowing eyes | gilding, 35% gilded plumes |
| 4 | pearl ahead | qi veins |

- **Jaw:** hinged at (0, −0.12, 0.2), with an opening angle of
  0.6·`eatMotion`·open rad: about 69° with `eatMotion` 2 (the Look tunable;
  1 is the first version's 34°). It opens fully when breathing fire or when
  `foodAhead()` finds food in reach.
  - `foodAhead()` is a scan run only for heads within 120 m.
  - Each bite snaps the jaw shut briefly.
  - The inside of the mouth is a funnel open at the front (`gapeGeo`, drawn
    from both sides with `throatMaterial`, deep red darkening toward the
    throat), 0.4 wide, 1.45 long and 0.02 + 1.15·tan(gap/2) tall, so a wide
    gape looks into a dark throat.
  - The snout lifts by 0.22·`eatMotion`·open (about 25°).
- **Look into turns:**
  - The turn rate comes from the quaternion change since last frame.
  - Yaw is clamped to ±0.8 and pitch to ±0.6, both ×`headLook` 0.3, smoothed
    with τ 0.12 s.
  - The head pivots 0.7 head-sizes back, so it stays on the neck.

### 6.6 Effects
- **Food:** one InstancedMesh of icosahedra, capped at 6,000. Colours are pushed
  above 1 so they bloom.
- **Power-up crystals** snap between shapes on a beat, like Tron's "Bit", and

- **Dragonfire:** a pooled additive cone sized by `breathStats` for the
  charges spent, plus 26 + 12k flame particles per frame.
- **Breath elements:**
  - Crystals: an ice shard, a violet lightning star and a green acid bubble,
    as big and loud as fire's, each shedding its own particles.
  - Ice: the same cone in frost blue, with snow. Lightning: sparks at the
    mouth, then `zap` draws jagged, flickering ribbons (glow + core) from the
    mouth through every dragon struck, following them for 0.45 s: one mesh
    for all bolts, up to 360 quads. Acid: a spray, then one swirling, rim-lit
    green ball per cloud (`acidMaterial`), with bubbles.
  - Chilled dragons go frost-white and shed snow; stunned ones flicker violet
    and crackle with sparks.
  - Particle hues: 0 fire, 1 ice/lodestone blue, 2 acid green, 3 lightning.
- **Sun crystals** (§3.4): the same crystals plus an ink-ring sprite each
  (normal blending, depth test off, so it reads on the sun's glare), a spark
  trail, and a pooled flare ring (up to 6) with a spark burst at each birth.
  Online they are kept by id and placed on the server's clock like pearls.

| Piece | Where | How it ships |
|---|---|---|
| Site | GitHub Pages, custom domain `skywyrm.io` (+ `www`) | `ci.yml` `deploy` job: runs after `checks` passes on a push to `main`, then configure-pages → upload `site/` → deploy-pages |
| Server | Cloud Run `wyrm-server`, project `dendros-wyrm` (display name "Skywyrm"), us-west1 | Cloud Build trigger on `^main$` in `joelisjoel/skywyrm`. Builds `/Dockerfile` when `server/**`, `site/js/**` or `Dockerfile` change |

**Cloud Run settings:**
- Public, with request-based billing.
- Instances: min 0 and **max 1**. Every room lives in one process, so raising
  this would split rooms between instances.
- 512 MiB of memory and 1 CPU.
- Timeout 3600 s, which ends every socket after 60 minutes. The game
  reconnects through it (§4.4).
- Concurrency 250.
- Service account `wyrm-server`, with the Cloud Datastore User role.
- URL: `https://wyrm-server-420365023329.us-west1.run.app`, hard-coded in
  `net-config.js:4`, and in `privacy.html`'s link to the public totals.

**Environment variables:**
- `ALLOWED_ORIGINS`: leave unset, so the code default (skywyrm.io and
  www.skywyrm.io) applies.
- `STORE`, `WYRM_TUNE`, `ALLOW_LOCALHOST` and `MAX_CONN_PER_IP` (sockets per
  IP, default 16): optional.

**The image:**
- `node:22-slim`.
- `npm ci --omit=dev` from `server/package-lock.json`.
- Copies `site/js` and `server`.
- Runs as `USER node`.
- `CMD node server/server.js`.

**Operations:**
- Rollback: send traffic to an earlier revision under Revisions.
- Kill switch: set max instances to 0.
- Budget alert: $20 a month.
- On SIGTERM the server closes, counts every room life it is about to cut off
  (held seats included) as `disconnect`, closes every socket with 4010 so
  browsers reconnect to the new revision at once, saves the day's totals and
  exits 500 ms later (at most 5 s after the signal; Cloud Run allows 10).
  Dragons don't survive a restart, so players start a new life.

**History.** The game lived in `dendroslabs/dendroslabs.github.io` until Oct 11, 2026.
It moved here with its history (rewritten with `git filter-repo`). The old copy
at dendroslabs.com/wyrm has been removed.

## 9. Security and abuse

**In place:**
- No accounts, chat, ads, cookies or third-party analytics. Nothing secret in
  the repo, since Cloud Run uses its service account.
- **Play and visit totals (§4.7, §4.8)** are anonymous by construction: a
  note carries no id, name or cookie, the server adds it straight into daily
  counts (each of a visit note's fields into its own counter), and
  `/api/stats` publishes only those counts. A visit's referrer is reduced to
  a category and its first-visit date to a bucket on the device. IPs are used only in the
  in-memory rate limits and are never stored or logged by the app. The
  privacy page (`site/privacy.html`) says exactly this.
- Production Firestore rules deny all browsers.
- Names are filtered on both the client and the server, and shown only with
  `textContent` or `fillText`. The filter (`names.js`):
  - folds accents to ASCII (José → Jose) and refuses any other letter, so a
    Cyrillic look-alike can't sneak a word past it
  - reads leetspeak, ph/ck/v sound-alikes, repeated letters and spaced-out
    letters
  - checks short words inside each word of a name, excusing innocent words
    they hide in (Grape, Peacock); `kys` and a few abbreviations only match
    as whole words
  - matches reserved words as whole words (Admin is taken, Systemic isn't)
- Room names are generated from word lists, never typed, so nothing a
  player writes is shown in every lobby (§4.4).
- Invite links (§5.6) carry only a room id (already public in
  `/api/rooms`) and `src=invite`. `?room=` is checked against the id format
  and only compared with listed ids; the share text uses only generated
  names.
- The origin allowlist, rate limits and frame limits in §4.6.
- An exception in a room's tick resets that room only, and one in a message
  closes only its sender, never the process (§4.4).

**Risks**

| # | Risk | Notes |
|---|---|---|
| 1 | Room-creation denial of service | 3 creations per hour per IP and a 12 h lifetime for unjoined rooms. One address can fill all 30 slots in about 10 h. The per-IP counts reset on restart |
| 2 | Shared networks | 16 sockets per IP (it was 6) still blocks the 17th player on one school or home network; `MAX_CONN_PER_IP` on Cloud Run raises it. The trade-off: one address can hold more player slots (16 of a room's 30). Seats held for a reconnect count toward the 16, so dropping sockets over and over can't fill a room |
| 3 | Scripted clients | `Origin` can be forged and there is no auth. Pose is client-reported within the speed budget. Perks aren't checked against rank. Lives are client-only. Accepted for a kids' game |
| 4 | Slow connections | Only snapshots are skipped under backpressure now, so `dn`, `dx` and `e` always arrive (§4.6). A stalled client's dragon hangs where its last pose put it, still hittable, until it catches up, its socket closes, or it falls 4 MB behind (4009) |
| 5 | Client IP | Uses the last `X-Forwarded-For` entry. That's correct behind Cloud Run directly, but a load balancer in front would put every player behind one IP |
| 6 | Capacity | One thread runs every room, with no tick-overrun metric. A room waking runs a synchronous 300-tick warm-up that stalls the other rooms |
| 7 | Hourly disconnect | The 3600 s timeout still ends every socket, but the browser reconnects and the server holds the dragon for it (§4.4). Dragons live in memory only, so a server restart (a deploy) still costs everyone their current life. A dropped player who never comes back holds a seat for up to 33 s |
| 8 | Third-party code | Fixed: three.js and the fonts are self-hosted and a CSP (meta tag) allows only this site and the game server. GitHub Pages can't send headers, so `frame-ancestors` isn't set |
| 9 | Unpinned builds | Lockfiles are committed and the image installs with `npm ci`; GitHub Actions are pinned by SHA. The Docker base image (`node:22-slim`) is still a tag, so it picks up Node security patches |
| 10 | Fake run and visit notes | Anyone can post plausible solo notes (20 an hour per IP) or visit notes (30 an hour per IP), more from many IPs, and skew those totals. Room totals are counted by the server and can't be faked this way. Read solo and visit numbers as a trend, not exact counts. The other way round, a big class on one address can send more than 30 visit notes in an hour, and the rest go uncounted |
| 11 | Host logs | Google Cloud's standard request logs (30 days) and GitHub Pages' logs record IP addresses, outside the app's control. The privacy page says so |
| 12 | Small counts | The totals are public. On a quiet day a count of 1 (a link tag, a return bucket) stands for a single visit. It says nothing about who, and counts can't be joined to each other, but don't add tags or buckets narrow enough to point at one family |
